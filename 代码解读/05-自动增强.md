# 05 · 自动增强：`automatic.py` + `review.py` + `workers/vision_worker.py`

这一层回答：**基础 OCR 认不准的地方（盖章、模糊、表格），怎么用视觉大模型二次精读，又怎么防止"精读结果其实更错"？**

先理清三个文件的分工：
- `automatic.py`：决策者——哪些页要增强、选哪些区域、最终采用谁的话。
- `review.py`：办事员——真正去调视觉模型、把候选结果存进 `vision_candidates` 表。
- `vision_worker.py`：计算工——在独立 venv 里裁图、跑 PaddleOCR-VL、输出文字。

---

## 一、`automatic.py`（232 行）—— 决策者

### 1. 画像与版本

```python
PROFILE = json.loads((Path(__file__).parent/'profiles/company_history.json').read_text(encoding='utf-8'))
SELECTION_VERSION = 'automatic-regions-identity-number-guard-v2'
UNKNOWN = '〔该区域信息无法可靠识别〕'
```

- PROFILE 是"章节画像"：想找哪些关键词（注册资本、股东名称、验资报告……）。注释强调：**画像只描述"关注什么"，里面没有任何答案**——不是把样例报告的事实硬塞给程序。
- 增强版本 = sha256(画像 JSON + 选择规则版本 + 视觉模型指纹 + 区域预算)。任何一样变了，旧增强结果自动失效。

### 2. `route_page()` —— 这页值不值得增强？

```python
def route_page(page, filename=''):
    text = normalized(page.get('text', ''))          # 去掉所有空白，方便匹配
    for old, new in PROFILE['ocr_aliases'].items():   # OCR 常见错字矫正："注册资木"→"注册资本"
        text = text.replace(old, new)
    hits = {name: [w for w in words if w in text] for name, words in PROFILE['groups'].items()}
    ...
    poor = not text or '\ufffd' in text or (len(text) < 8 and any(t in filename for t in PROFILE['material_hints']))
    return dict(important=bool(hits), needs_vision=page['method']=='ocr' and (important or poor), ...)
```

三路判断：
- **important**：命中了画像里的关键词组（6 组：主体登记/资本股权/设立变更/合并分立/出资依据/权利限制）。注意别名替换**只用于匹配**，不会去改原始 OCR 文字——注释特意说明这是"线索"，不是篡改。
- **poor**：文字是空的 / 含乱码符 / 文字极少但文件名像工商材料（"工商、章程、验资"……）。文字太少没法判断，宁可信它是重要页。
- `needs_vision` 额外要求 `method=='ocr'`：**PDF 自带文字层的页不增强**——原生文字比 OCR 可靠，没必要再花几百秒跑视觉模型。

### 3. `regions_for()` —— 在页面上圈出要精读的区域

这是全项目最"几何"的函数。思路：重要关键词在**文字**里的位置 → 反查它对应的 OCR **行框** → 行框连成窗口 → 换算成图片裁剪坐标。

```python
with path.open('rb') as stream:
    header = stream.read(24)
if header[:8] != b'\x89PNG\r\n\x1a\n': raise ValueError()
width, height = struct.unpack('>II', header[16:24])
```

先读 PNG 文件头拿图片尺寸（PNG 头 8 字节魔数 + IHDR 块里 16–24 字节是宽高）。不加载整张图，24 字节搞定。

```python
for line in lines:
    start = text.find(line['text'], cursor)
    if start < 0: raise ValueError()
    offsets.append((start, start+len(line['text']))); cursor = start+len(line['text'])
```

把每行 OCR 文字"对号入座"到整页文本里：从头顺序 `find`，记录每行在整页文本中的起止偏移。`cursor` 往前推进保证同名文字不会匹配到前面去。任何一行找不到（顺序错乱）→ 整个失败 → **退回整页方案**（裁剪 [0,0,1,1] 全页），注释说得很清楚："不是把该页直接忽略"。

```python
for i in anchors:
    first, last = max(0,i-1), min(len(lines)-1, i+2)     # 重要行 ± 1 行 = 上下文窗口
    if windows and first <= windows[-1][1]+1 and last-windows[-1][0] < 10:
        windows[-1] = (windows[-1][0], last)              # 相邻窗口合并，避免碎片化
```

重要行的前一行和后两行一起纳入窗口——**字段值常在关键词的下一行**（比如"注册资本："在上一行、"1000万元"在下一行）。

```python
box = [max(0,(min_x-12)/width), max(0,(min_y-12)/height), min(1,(max_x+12)/width), min(1,(max_y+12)/height)]
```

窗口内所有行的所有角点取最小/最大 → 外扩 12 像素（防止裁太紧切掉字边）→ 除以宽高得到 **0–1 归一化坐标**。为什么归一化？渲染比例可能变（2 倍变 3 倍），归一化坐标与像素尺寸无关，裁剪结果稳定。

```python
for i, region in enumerate(regions): region['over_budget'] = i >= limit
```

**超预算的窗口照样返回**，只是标记 over_budget。下游会把这些区域直接标"未知"——绝不因为"没调模型"就假装处理完了。这是诚实覆盖原则的落地点。

### 4. `choose_region()` —— 机器裁判：到底信谁？

输入是"基础 OCR 的这段文字 base"和"视觉模型对同一区域的识别 candidate"，输出三选一：consistent（一致，保留 base）/ enhanced（采用视觉）/ unknown（掩码）。

```python
if not candidate or candidate.get('truncated') or not candidate.get('text','').strip():
    return dict(decision='unknown', text=mask_unknown(base), reason='视觉失败、空结果、预算限制或截断')
```

第一关：候选不存在/被截断（worker 显式报告的）/是空的 → 直接 unknown。**截断的文字不能当全文用**。

```python
old = list(re.finditer(r'(\d{2,4})年', base)); new = list(re.finditer(r'(\d{2,4})年', visual))
if len(old) == len(new):
    for left, right in reversed(list(zip(old, new))):
        if not 1900 <= int(left[1]) <= 2100 and 1900 <= int(right[1]) <= 2100:
            iterator = iter(right[1])
            if all(char in iterator for char in left[1]):
                repaired = repaired[:left.start(1)] + right[1] + repaired[left.end(1):]
```

第二关（唯一的"修复"）：OCR 常把"二〇〇三"认成"二〇三"（少个零）。规则：两边"X年"数量相同、OCR 侧年份不在 1900–2100 合法范围、视觉侧合法、且 OCR 的数字是视觉数字的**子序列**（"二〇三"每个字按顺序都在"二〇〇三"里）——才允许替换。**为什么这么苛刻？** 修复是危险的：修好了锦上添花，修错了就是篡改证据。所以只在"不会更糟"的狭窄条件下修。

```python
same_numbers = numbers(repaired) == numbers(visual)      # 所有数字（含千分位）序列一致
same_units = units(repaired) == units(visual)            # 亿元/万元/元/% 序列一致
same_identity = identity_values(repaired) == identity_values(visual)  # "企业名称：XX"这类标签值一致
```

第三关是三组硬校验。`numbers()` 用 `Decimal` 解析（避免浮点误差），千分位逗号先去掉；`identity_values()` 用正则抓 9 种标签（企业名称/法定代表人/统一社会信用代码/注册号……）后面的值。**为什么金额差异不能"谁像对的信谁"？** 因为两路给出不同但各自合法的金额时，程序没有立场裁决哪个是真的——注释原文就是这么写的。

```python
def valid_dates(text):
    for y, m, d in re.findall(r'(\d{2,4})年(\d{1,2})月(\d{1,2})日', text):
        try:
            if not 1900 <= int(y) <= 2100: return False
            date(int(y), int(m), int(d))
        except ValueError: return False
    return True
```

第四关：视觉侧的日期必须真的存在（2月30日不行）。**"两个模型都认错成同一个假日期"也照样判 unknown**。

```python
similarity = SequenceMatcher(None, normalized(repaired), normalized(visual)).ratio()
if not same_numbers or not same_units or not same_identity or not valid_dates(visual) or similarity < .72:
    return dict(decision='unknown', text=mask_unknown(base), reason='...无法消解')
if normalized(base) == normalized(visual):
    return dict(decision='consistent', text=base, reason='两路文字一致；仅为机器核对')
return dict(decision='enhanced', text=visual, reason='位置与文字对应，数值／单位保护通过')
```

最后一关：整体相似度 ≥72%。全部通过后：一字不差 → consistent；有差异但校验全过 → enhanced（采信视觉）。**注意返回文案的克制：consistent 的理由写的是"仅为机器核对"**——不是"已核实"。

```python
def mask_unknown(text):
    return UNKNOWN
```

`mask_unknown` 扔掉原文返回统一掩码。注释解释了为什么不留原文：**字段值常延续到下一行，保留被拒区域的残留文字，等于把一个"可能认错的法定代表人"继续当证据用**。宁可丢信息，不交假信息。

### 5. `AutomaticProcessor.process()` —— 把上面的零件串起来

每页的流程：
1. checkpoint（响应暂停）；
2. 查历史：同 base_revision + 同增强版本已有结果且不是 uncertain（或已试 ≥2 轮）→ skip；
3. `route_page` 判断；需要增强则 `regions_for` 圈区域；
4. 逐区域：先查 `vision_candidates` 缓存（同页+同修订+同坐标+同版本的成功候选直接复用），没有才调 `review.recognize`；
5. `choose_region` 裁决 → 区域列表按 start **倒序**回填文字（倒序是为了前面的替换不改变后面区域的偏移）；
6. 汇总 outcome（uncertain/enhanced/checked/base）；
7. 写库前再锁一次源页行、重比修订（**视觉模型跑的几百秒里，基础 OCR 可能被别人更新了**）——变了就整页记失败，绝不把视觉结果绑到错的底稿上；没变则追加一条 `machine_pages`。

**只追加、不修改**：原始 `document_pages` 永远不被写坏，"数据库视图"（effective_document_pages）决定当前用谁的话。

## 二、`review.py`（122 行）—— 视觉候选的持久化服务

### `LocalVision.profile()` —— 视觉模型指纹

```python
digest = hashlib.sha256(b'vision-region-v1-cpu-fp32')
for file in sorted(self.settings.vision_models_dir.glob('*')):
    if file.suffix in {'.safetensors', '.json'}:
        digest.update(file.name.encode())
        with file.open('rb') as stream:
            for block in iter(lambda: stream.read(4*1024*1024), b''): digest.update(block)
digest.update(str(self.settings.vision_timeout_seconds).encode())
```

safetensors + json 逐字节哈希，连推理超时配置也算进去。这就是增强版本里"视觉模型指纹"的来源。

### `recognize()` —— 调用前后各验一次修订

```python
state = self.state(project_id, document_id, number)
if state['raw_revision'] != raw_revision:
    raise ReviewConflict('页面已更新，请刷新后选择识别区域。')
...
with model_slot(self.settings.data_dir):        # 模型资源锁！
    result = self.vision.recognize(image_path=image, bounds=bounds, directory=directory)
    ...
status = 'succeeded' if self.state(...)[ 'raw_revision'] == raw_revision else 'stale'
```

- 调用**前**：确认页面还是发出请求时的那个版本。
- **模型锁**：视觉推理和向量检索共用一把跨进程文件锁（防两个模型同时把 CPU/内存挤爆）。
- 调用**后**：如果页面在推理期间变了，状态记 `stale` 而不是 `succeeded`——结果照存（留档），但不会被当有效候选复用。
- 先插一条 `running` 记录再推理，最后 UPDATE 成功/失败/过期——即使进程崩了，表里也有痕迹可查。

### `state()` —— 历史查询

返回页面的原始修订号、旧人工采纳记录（adoptions，**仅留档**，现在的自动流程不使用）、视觉候选列表、"人工采纳与当前修订是否冲突"的标志。这个文件叫 review 是历史遗留（早期版本是人工复核工具），现在它只是视觉候选的基础设施。

## 三、`workers/vision_worker.py`（102 行）—— PaddleOCR-VL 小工

跑在 `.venv-vision`。每调用一次 = 识别**一个**区域。

### 裁剪

```python
def crop_region(image, bounds):
    box = [math.floor(bounds[0]*width), math.floor(bounds[1]*height),
           math.ceil(bounds[2]*width), math.ceil(bounds[3]*height)]
    return image.crop(box), box
```

左上向下取整、右下向上取整——**宁可多裁一点，不切掉边缘的字**。裁剪前校验坐标合法性和图片尺寸（上限 1200 万像素，防超大图撑爆内存）。

### 加载模型的两个坑

```python
config = AutoConfig.from_pretrained(path, local_files_only=True)
if hasattr(config, 'text_config'):
    config.text_config.tie_word_embeddings = False
config.tie_word_embeddings = False
model = AutoModelForImageTextToText.from_pretrained(path, config=config, dtype=torch.float32,
            attn_implementation='eager', local_files_only=True).to('cpu').eval()
```

- `tie_word_embeddings=False`：这个模型（PaddleOCR-VL）的输入/输出词嵌入**不共享权重**，但 Transformers 配置转换时可能错误地改成共享——这里显式关掉，否则模型输出乱码。
- `eager` 注意力 + `float32` + CPU：纯本机推理，精度优先速度。

### 生成与"截断"的诚实报告

```python
messages = [{'role':'user', 'content':[{'type':'image','image':picture}, {'type':'text','text':'OCR:'}]}]
```

提示词**只有 'OCR:'**——故意不带基础 OCR 的猜测、不带报告答案，**防止模型被"诱导"顺着已有答案抄**（这叫答案反向污染）。

```python
output = model.generate(**inputs, max_new_tokens=payload['max_new_tokens'], do_sample=False)
tokens = output[0, inputs['input_ids'].shape[-1]:]     # 只取新生成的部分
truncated = bool(len(tokens) >= payload['max_new_tokens'] and int(tokens[-1]) not in eos)
```

- 解码时切掉输入部分，只留模型生成的 token。
- **truncated 判定**：生成数顶到了上限、且最后一个 token 不是结束符 → 明确报告"我没说完"。主进程的 `choose_region` 见到 truncated 直接判 unknown。对比很多应用"默默截断还当全文用"，这里是诚实的。
- 输出还带：模型指纹、裁剪图 SHA-256、裁剪框、耗时、峰值内存（Windows 用 ctypes 调 psapi 查）——**每个候选都能追溯到"哪张图、哪个模型版本、跑了多久"**。

## 本篇小结

- `automatic.py`：路由（该不该增强）→ 选区（几何计算）→ 裁决（五重校验，不过就掩码）。核心哲学：**修复要苛刻，裁决要保守，宁可标未知。**
- `review.py`：调用前后双重修订校验 + 候选状态机（running/succeeded/failed/stale）。
- `vision_worker.py`：干净的 'OCR:' 提示防污染、显式 truncated 报告、完整可追溯的元数据。
