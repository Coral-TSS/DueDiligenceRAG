## 一、`storage.py`（76 行）—— 原件文件怎么存

这个文件只管一件事：**上传的文件安全地落盘**。数据库登记不归它管（那是 db.py），怎么解析也不归它管。

### 1. 文件名清洗

```python
def clean_filename(name):
    basename = (name or "未命名文件").replace("\\", "/").rsplit("/", 1)[-1]
    return re.sub(r"[\x00-\x1f\x7f]", "", basename)[:240] or "未命名文件"
```

两步防御：
- `rsplit("/", 1)[-1]`：有人上传时文件名可能带路径（`C:\Users\xx\材料.pdf`），只留最后一段，防止"路径注入"。
- `re.sub(r"[\x00-\x1f\x7f]", ...)`：删掉所有控制字符（ASCII 0–31 和 127，这类字符可能让文件系统/日志出乱子）。
- 最后 `or "未命名文件"`：万一清洗完变空串，给个兜底名字。

### 2. `save()` —— 核心方法，逐段讲

```python
staging = self.root / "staging"
staging.mkdir(parents=True, exist_ok=True)
descriptor, temporary = tempfile.mkstemp(dir=staging, suffix=".part")
```

先写到一个 `.part` 临时文件——**好处：写一半崩了，正式目录里不会留下半个坏文件**。

```python
with os.fdopen(descriptor, "wb") as output:
    while block := stream.read(1024 * 1024):     # 每次读 1MB
        size += len(block)
        if size > self.limit:
            raise UploadTooLarge()                # 超限立即中止
        digest.update(block)                      # 边写边算 SHA-256
        output.write(block)
    os.fsync(output.fileno())                     # 强制刷到磁盘
```

- `while block := ...` 是海象运算符（Python 3.8+）：读一块、判断非空、用这个块，一行搞定。
- **为什么 1MB 一块地读写？** 如果一个 500MB 的 PDF 一次性读进内存，内存直接爆。流式处理内存占用恒定 1MB。
- `digest.update(block)`：SHA-256 可以流式累算，读完就是整个文件的指纹。

```python
if size == 0:
    status, reason = "invalid", "文件为空..."
elif not filename.lower().endswith(".pdf"):
    status, reason = "unsupported", "当前阶段仅登记 PDF..."
elif head != b"%PDF-":
    status, reason = "invalid", "未识别到 PDF 文件头..."
else:
    status, reason = "registered", "已登记，待解析..."
```

三种坏情况分开标记：空文件、非 PDF 扩展名（登记但暂不解析）、伪装成 PDF 的文件（扩展名对但开头 5 字节不是 `%PDF-`）。注意 `head` 是在读块时偷偷留的前 5 字节。

```python
sha = digest.hexdigest()
key = f"documents/{project_id}/{sha}.bin"
target = self.path(key)
try:
    os.link(temporary, target)       # 硬链接发布
except FileExistsError:
    pass                             # 已存在同内容文件，不覆盖，直接用旧的
```

**存储名不叫原来的文件名，而是"项目ID + 内容指纹"**——这叫内容寻址：
- 同一份文件传两次（哪怕改了文件名），磁盘上永远只有一份字节；
- 硬链接比复制快得多且不占额外空间；
- `FileExistsError` 被静默吞掉是故意的：并发上传同一文件时，后到的直接复用先到的。

```python
finally:
    Path(temporary).unlink(missing_ok=True)
```

`finally` 保证无论成功失败都删临时文件（硬链接成功后删的只是"另一个名字"，正式文件还在）。`missing_ok=True`：本来就不存在也不报错。

### 3. `path()` —— 防目录穿越

```python
def path(self, key):
    path = (self.root / key).resolve()
    if not path.is_relative_to(self.root):
        raise ValueError("Invalid storage path")
    return path
```

哪怕 key 来自自家数据库，也要防一手：如果 key 被篡改成 `../../敏感文件`，`resolve()` 解析出真实路径后一比，发现跑到了数据目录外面，直接拒绝。`.resolve()` 会把 `..` 这类相对部分消解成真实绝对路径，所以这个检查是可靠的。

## 二、`db.py`（160 行）—— 数据库访问层

**特点先说清**：没有 ORM（不用 SQLAlchemy 那种"把表映射成类"的框架），直接写 SQL。优点是所见即所得、SQL 能力全开；代价是要自己保证 SQL 正确。

### 1. 连接管理

```python
def connect(self):
    if not self._url:
        raise psycopg.OperationalError("Database not configured")
    return psycopg.connect(self._url, connect_timeout=3, row_factory=dict_row)
```

- 每次操作都开新连接（本项目是本机单人应用，连接开销可忽略；不搞连接池是刻意保持简单）。
- `row_factory=dict_row`：查询结果按"列名 → 值"的字典返回，`row['page_count']`，而不是 `row[3]` 这种魔法数字。
- 调用方一律 `with self.connect() as conn:`——psycopg 的约定：with 块正常结束自动提交，抛异常自动回滚并关连接。

### 2. `health()` —— 体检

依次尝试连接 → 查 schema 版本号，返回四种状态之一：
`needs_configuration`（没配 .env）→ `needs_migration`（连上了但没建表/版本不符）→ `database_unavailable`（连不上）→ `ready`。网页顶部的连接横幅就是吃这个接口。注意它**不读任何业务数据**。

### 3. `migrate()` —— 幂等建表

```python
with self.connect() as conn:
    conn.execute("SELECT pg_advisory_xact_lock(74332101)")
    for source in sorted((Path(__file__).parent / 'migrations').glob('*.sql')):
        conn.execute(source.read_text(encoding='utf-8'))
```

- 先拿一把数据库锁：两个应用同时初始化也不会打架。
- 然后按文件名顺序把 6 个 SQL 全部执行一遍。**为什么重复执行不出事？** 因为每个迁移 SQL 都写成幂等形式（`CREATE TABLE IF NOT EXISTS`、`INSERT ... ON CONFLICT DO NOTHING`）——跑一百遍结果都一样。
- `schema_version` 表记录版本号，`health()` 靠它判断"要不要迁移"。

### 4. 材料登记：去重的正确写法

```python
row = conn.execute(
    """INSERT INTO dd_agent.documents (...) VALUES (...)
    ON CONFLICT (project_id, sha256) DO NOTHING RETURNING *""", ...).fetchone()
duplicate = row is None
if duplicate:
    row = conn.execute("SELECT * FROM dd_agent.documents WHERE project_id=%s AND sha256=%s", ...).fetchone()
conn.execute("INSERT INTO dd_agent.document_sources ... ON CONFLICT DO NOTHING", (row["id"], stored["filename"]))
```

注释点破了要点：**"不要先查'没有'再无条件插入"**。如果先 SELECT 发现已存在再 INSERT，两个请求同时到达时都会"发现不存在"，然后都插入——除非有唯一约束兜底。`ON CONFLICT DO NOTHING` 一条语句原子完成"存在就跳过"，靠的是 `(project_id, sha256)` 唯一约束。重复时把新文件名追加进 `document_sources` 表——内容同、来源名不同的多份文件共享同一条材料记录。

### 5. 阅读版本切换：不删历史

```python
def set_reading(self, document_id, page_count, version):
    conn.execute('''INSERT INTO dd_agent.document_readings ...
        ON CONFLICT (document_id) DO UPDATE SET page_count=EXCLUDED.page_count, ...''', ...)
```

`document_readings` 每个材料一行，记录"当前用的是哪个阅读版本"。注意 `save_page()` 的主键是 `(document_id, page_number, pipeline_version)`——**换版本时旧版本的全部页面还在表里**，只是不再被"当前"查询返回。这是全项目"只追加、不覆盖"原则的体现。

### 6. `reading()` —— 状态归并

```python
row['status'] = 'complete' if row['successful_pages']==row['page_count'] else \
    'partial' if row['successful_pages'] else \
    'failed' if row['failed_pages'] else 'not_started'
```

把"页级成功/失败计数"翻译成四个用户看得懂的状态：全读完 / 读了一部分 / 全失败还没成功过 / 还没开始。**它数的是"基础阅读"的页**，和增强、向量化无关——网页上"全卷已读"徽章用的就是它，所以界面文案反复强调"不等于全部处理完成"。

### 7. `material_catalog()` —— 键集分页

```python
rows = conn.execute('''... WHERE d.project_id=%s AND (%s::uuid IS NULL OR d.id>%s::uuid)
    ORDER BY d.id LIMIT %s''', (project_id, after, after, limit+1)).fetchall()
items = rows[:limit]
next_cursor = str(items[-1]['document_id']) if len(rows)>limit else None
```

分页不取"第 101–150 条"（OFFSET 方式），而是"给我 id 大于上一批最后一条的 50 条"（keyset 方式）。好处：中途有新数据插入也不会错位重复。多取一条（`limit+1`）用来判断"还有没有下一批"。游标还要验证属于本项目，防止拿别处的 id 来探测。

## 本篇小结

- `storage.py`：流式写 + 内容寻址 + 硬链接去重 + 路径穿越防护。**记住核心思想：文件按"内容"存，不按"名字"存。**
- `db.py`：裸 SQL 但纪律严明——原子去重靠唯一约束、迁移靠幂等 SQL、分页靠 keyset、历史版本只留不删。
