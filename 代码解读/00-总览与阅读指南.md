# 00 · 总览与阅读指南

> 这套文档把 `src/dd_agent/` 里每一个 Python 文件都掰开揉碎讲一遍。
> 假设你刚学 Python 不久，遇到语言特性（装饰器、生成器、dataclass 等）都会现场解释。

## 一、这个项目在干什么（一句话版）

把尽调用的 PDF 材料传进来 → 自动识别文字（普通 PDF 直接提取，扫描件用 OCR）→ 对重要区域用视觉模型二次精读 → 把文字切成小块算成向量存进 PostgreSQL → 你输入问题，它找出最相关的原文片段给你。

**它不会帮你写报告**——目前只到"找出候选证据"这一步，生成报告是后续任务。

## 二、先补几个 Python 概念（后面会反复出现）

| 概念 | 一句话解释 | 在本项目哪里出现 |
| --- | --- | --- |
| `dataclass(frozen=True)` | 一个"只读数据盒子"：自动生成 `__init__`，frozen 表示字段不可改 | `config.py` 的 Settings |
| `@contextmanager` | 把一个函数变成能配合 `with` 用的东西：`yield` 前 = 进 with 时执行，`yield` 后 = 出 with 时执行 | `retrieval.py` 的 model_slot |
| 生成器（`yield`） | 函数不一次性返回所有结果，而是"挤牙膏"式一个一个吐，收到一个处理一个 | `worker_records()`、`embed_pages()` |
| 装饰器 `@app.get(...)` | 给函数"贴标签"，让 FastAPI 知道这个函数对应哪个网址 | `app.py` 全部路由 |
| `with conn.connect() as conn:` | 进 `with` 开数据库事务，正常结束自动提交，抛异常自动回滚 | 所有数据库操作 |
| `uuid4()` | 生成一个全球唯一的随机 ID（36 位字符串） | 所有表的 id |
| `psycopg` | Python 连 PostgreSQL 的库，本项目直接写 SQL，没有 ORM | `db.py` |
| advisory lock | PostgreSQL 自带的"全局锁"，存在与否不占表数据，断连自动释放 | 调度队列的核心 |
| pgvector | PostgreSQL 扩展，能存向量（一串浮点数）并按"距离"快速搜索 | 证据检索 |
| JSONL | 每行一个独立 JSON 的文本格式，适合进程间逐条传数据 | 主进程 ↔ worker 协议 |

## 三、进程全景图

```
你电脑上同时存在的进程（正常处理一份材料时）：

┌─────────────────────────────────────────────────────┐
│ 主应用进程 (.venv-dev)                                │
│  FastAPI 网页服务 + 后台调度线程 + 数据库访问           │
│  它自己不跑任何模型！                                   │
└──────┬──────────┬──────────┬──────────┬─────────────┘
       │按需拉起   │          │          │
       ▼          ▼          ▼          ▼
  pdf_worker  ocr_worker  vision_   retrieval_worker
  (.venv-docling)(.venv-ocr) worker  (.venv-retrieval)
  提取文字+    PaddleOCR   (.venv-    Qwen3向量/
  渲染图片     基础识别     vision)    重排模型
                          区域精读
每个 worker 都是"启动→干活→退出"的短命进程，用完即走。
```

## 四、数据在数据库里的分层（记住这个再读代码）

```
projects（项目）
  └─ documents（材料，按内容摘要去重）
       ├─ document_pages      ← 第1层：基础阅读的原始文字（按阅读版本存多份）
       ├─ machine_pages       ← 第2层：自动增强结果（只追加，不改原文）
       ├─ effective_document_pages ← 视图：综合上两层，给出"当前该用的文字"
       ├─ indexed_pages       ← 第3层：哪些页已建索引（页级登记）
       │    └─ evidence_chunks ← 切成的文字块 + 1024 维向量
       ├─ vision_candidates   ← 视觉模型的区域识别记录（可缓存复用）
       └─ processing_jobs     ← 处理任务的排队/暂停/进度
```

| 序号 | 文件 | 内容 |
| --- | --- | --- |
| 01 | 入口与配置 | `__main__.py`、`config.py`、`control.py` —— 程序从哪里启动、配置从哪来 |
| 02 | 存储与数据库 | `storage.py`、`db.py` —— 文件存哪、数据存哪 |
| 03 | Web 应用 | `app.py` —— 所有网页接口 |

## 六、贯穿全局的三条主线（读代码时心里绷着这根弦）

1. **版本链**：OCR 权重换一个字节 → 阅读版本变 → 增强结果作废 → 旧向量不被检索。每一层的版本号都是算出来的指纹，不是手写的标签。
2. **先落库再暂停**：任何阶段（一页 OCR、一个区域、一页向量）都是"先提交数据库，再检查要不要暂停"。所以随时停下都不丢已完成的工作。
3. **机器结果 ≠ 事实**：代码里到处在防御"把机器输出当成真的"。两路文字一致只标"机器一致"，校验不过宁可整块标"未知"。读代码时看到一大堆校验，都是为这条服务的。
