## 一、`__main__.py`（133 行）—— 程序的大门

**文件名为什么叫 `__main__.py`？** 这是 Python 的约定：当你在包目录（`dd_agent/`）下放一个叫这个名字的文件，执行 `python -m dd_agent` 时 Python 就会运行它。相当于 C 语言的 `main()` 函数。

### 1. 开头的 import

```python
import argparse      # Python 自带的命令行参数解析器
import sys
import json
from pathlib import Path    # 面向对象的文件路径
from uuid import UUID

import psycopg       # PostgreSQL 数据库驱动
import uvicorn       # 跑 FastAPI 网页服务的服务器

from .config import Settings    # 注意开头有个点！表示"从我的包 dd_agent 里导入"
from .db import Database
```

> ⚠️ **新手最容易踩的坑**：`from .config import ...` 开头这个点叫"相对导入"，意思是"从我自己所在的包里找 config 模块"。正因为有相对导入，这个文件**不能直接右键运行**（PyCharm 会报 `ImportError: attempted relative import with no known parent package`），只能用 `python -m dd_agent` 方式跑——这就是之前你启动失败的原因。

### 2. 命令行骨架

```python
parser = argparse.ArgumentParser(description="尽调材料本地工作区")
parser.add_argument("command", nargs="?", choices=["serve", "init-db", "check", ...], default="serve")
```

- `nargs="?"`：这个参数可给可不给。
- `default="serve"`：**什么都不输就等于 `serve`**，所以 `python -m dd_agent` 就是启动网页服务。
- choices 里的 10 个命令分四类：
  - **日常使用**：`serve`（启网页）、`init-db`（建表）、`check`（体检）、`harness-check`（AI 运行环境体检）
  - **完整处理**：`process-pages`（阅读+增强+索引一条龙）
  - **低层诊断**：`inspect-pdf` / `import-file` / `read-pages` / `index-pages` / `search`（只做某一步，用来排查问题）
- 后面的 `--file`、`--project-id`、`--pages '1-5,8'` 等是各命令的可选参数。

```python
try:
    settings = Settings.from_env()   # 读 .env 配置文件
except ValueError:
    print("配置无效：请检查 .env 中的目录、端口和文件大小上限。")
    return 1    # 返回非 0 表示程序以"失败"结束
```

### 3. 各命令分支在干什么

**`harness-check`**（第 34–41 行）：只检查 AI 运行环境（DeepSeek Harness）装没装好，不碰数据库不碰模型。

**`process-pages`**（第 42–60 行）：CLI 版的完整处理。注意它**直接调用 `ProcessingPipeline.run()`**，不经过网页那套排队队列——所以网页上的"暂停"按钮管不住它，注释里特意提醒了这点。返回值设计：增强或索引有失败页就返回 1（让脚本调用方知道有失败）。

**`index-pages` / `search`**（第 61–80 行）：只做向量索引或只做检索，纯诊断用。

**`inspect-pdf` / `import-file` / `read-pages`**（第 81–112 行）：
- `inspect-pdf --file 某文件.pdf`：数一数这 PDF 多少页、多少页有文字层、多少页是扫描件。
- `import-file --file xx.pdf --project-id xxx`：把本地文件登记进项目（等价于网页上传）。
- `read-pages`：只做基础阅读（提取文字/OCR），不做增强不做索引。`--force-ocr` 会忽略 PDF 自带文字层强制 OCR，用独立版本号存。

**`init-db`**（第 113–120 行）：执行数据库迁移建表。注释强调：**普通 `serve` 不会自动改数据库结构**，必须显式初始化——防止你不知不觉中表结构被改了。

**`check`**（第 121–124 行）：调 `database.health()` 打印一句状态。

**`serve`**（第 125–128 行，else 分支）：

```python
uvicorn.run(create_app(settings), host="127.0.0.1", port=settings.port)
```

- `host="127.0.0.1"` 写死：**只监听本机**，局域网里其他电脑访问不了——单人版的安全设计。
- 返回码约定：整个 `main()` 正常返回 0，各种失败路径返回 1。

## 二、`config.py`（73 行）—— 全部配置的集中地

### 1. 为什么用 frozen dataclass

```python
@dataclass(frozen=True)
class Settings:
    database_url: str = field(default="", repr=False)   # repr=False：打印对象时不显示这个字段
    data_dir: Path = ROOT / ".local" / "data"
    max_upload_bytes: int = 100 * 1024 * 1024
    port: int = 8765
    ...
```

- `@dataclass`：自动帮你生成 `__init__`，不用手写一坨 `self.xxx = xxx`。
- `frozen=True`：创建后字段不许改（改了会抛异常），配置就不怕被代码不小心改掉。
- `database_url` 加 `repr=False`：**打印 Settings 对象时不会把数据库密码打出来**，防泄露的小细节。
- `ROOT = Path(__file__).resolve().parents[2]`：从本文件位置往上跳 2 级 = 项目根目录。好处：不管你从哪个目录启动，项目根永远算得对。

### 2. 一堆 venv 路径字段

```python
pdf_python: Path = ROOT / '.venv-docling' / 'Scripts' / 'python.exe'
ocr_python: Path = ROOT / '.venv-ocr' / 'Scripts' / 'python.exe'
retrieval_python: Path = ...
vision_python: Path = ...
harness_python: Path = ...
```

这就是"每个模型一个虚拟环境"的配置落地。主应用记住"该去哪个环境里拉起 worker"，但它自己不用那些库。模型目录（`embedding_dir`、`reranker_dir` 等）只是**路径**，配置阶段不加载任何模型。

### 3. 参数合法性校验

```python
def __post_init__(self):
    if self.max_upload_bytes <= 0 or not 1 <= self.port <= 65535 or ...:
        raise ValueError("文件大小上限须大于 0，端口须在 1–65535 之间。")
```

`__post_init__` 是 dataclass 的钩子：`__init__` 跑完后立刻执行，用来做校验。端口输成 0 或 99999、渲染比例输成 8，**在启动那一刻就报错**，而不是跑到一半才炸。

### 4. `from_env()` —— 从 .env 文件读配置

```python
@classmethod
def from_env(cls):
    load_dotenv(ROOT / ".env")          # 把 .env 文件里的 KEY=VALUE 读进环境变量
    directory = os.getenv("DDA_DATA_DIR", "").strip()
    path = Path(directory).expanduser() if directory else ROOT / ".local" / "data"
    if not path.is_absolute():
        path = ROOT / path               # 相对路径以项目根为基准，不是"当前命令行目录"
    return cls(database_url=os.getenv("DDA_DATABASE_URL", "").strip(), ...)
```

套路是统一的：每个配置项 `os.getenv("环境变量名", "默认值")`——.env 里写了就用你的，没写就用默认值。`.env` 不进版本控制（里面有数据库密码），模板是 `.env.example`。

## 三、`control.py`（12 行）—— 最短但最讲究的文件

```python
class ProcessingPaused(Exception):
    """The user requested a persistent pause at a safe boundary."""

class ProcessingStopped(Exception):
    """Service shutdown; leave the job recoverable on startup."""
```

就两个空异常类，为什么值得单独一个文件？

因为**它们是控制信号，不是错误**。处理链路埋了一层层的 `try/except`，如果不把"暂停"和"OCR 识别失败"区分成不同类型，暂停信号就会在某个"捕获一切失败"的 except 里被吞掉——结果是你点了暂停，程序却把当前页记成"识别失败"继续跑。单独定义类型 + 单独一个文件（文件注释明确写着"不应在普通识别失败的 except 中吞掉它们"），就是用类型系统强制区分这两种情况。这是 Python 里"用异常类型表达控制流"的典型手法。

## 本篇小结

- `__main__.py` = 命令行大门，默认命令是 serve；**必须用 `python -m dd_agent` 方式运行**。
- `config.py` = 只读配置盒子，从 `.env` 读，启动即校验，不泄露密码。
- `control.py` = 两个"控制信号"异常，保证暂停不会被当成识别失败吞掉。
