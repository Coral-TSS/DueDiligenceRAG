# RG-05i 查询路径与公平调度验证

实施与验证日期：2026-10-28。任务状态仅维护于 `specs/01-evidence-to-report/tasks.md`。

## 交付范围

- `model_admission.py`：交互、后台各自 FIFO，共享有限等待队列；连续最多 3 个交互领取后，优先给仍在等待的后台一次。默认最多 8 个等待者，排队最多 3 秒；不抢占已经开始的页或区域。超时、取消移除队项，关闭唤醒等待者。
- `model_runtime.py`：队列、写管道、读取、加载和推理阶段接入请求控制。排队查询取消不结束别人的在途模型；自身推理取消回收所属实例。实际解释器和 JSONL 身份保护沿用 RG-05e。
- 常驻 OCR／Embedding 按页完成模型响应，再把结果交给保存端；视觉按区域。SQL、空结果、纯模型缓存命中不申请计算许可。检索一次性回退也在模型计算完成后释放文件锁；旧 OCR 一次性回退仍按原批次锁运行。
- `ProcessingDeferred`：后台仅因模型繁忙时归还未完成领取，延迟 0.2 秒再参与调度。尝试记录为 deferred／model_busy，不增加 failures；已发布页面保留。视觉候选关闭为 failed／model_busy，然后向上重排队，不发布未知机器页。
- `search_queries.py`：精确 pgvector 候选最多 12，最终最多 5；覆盖在数据库聚合，最终候选 ID 复验、文件名批量获取（每材料最多 50 个，超出标记 sources_truncated）。索引只读取本批最多 20 页。
- `model_results.py`：每个 EvidenceService 的纯模型结果内存缓存，最多 64 项／序列化值 16 MiB／TTL 300 秒。键绑定项目、实际模型描述、查询、候选文字顺序和内容摘要；失败、取消及无效数值不入缓存。无完整检索响应缓存；每次重新召回、来源复验和覆盖统计，新增材料立即可见。
- 搜索页取消按钮、AbortController、HTTP 断开信号、迟到结果丢弃；忙碌 503＋Retry-After: 1、取消 499、超时 504。数据库繁忙仍由原异常处理器响应，不被任务组包装为 500。

无新增依赖、权重或数据库迁移；业务库需要此前已交付的 008，本次只读检查已确认就绪。

## 边界

公平调度限同一应用进程、仍未取消或超时的等待者；跨进程沿用文件租约与忙碌反馈，没有全局队列。当前运行中的长页不会被查询抢占，不承诺固定墙钟等待时间。连续繁忙会延后后台处理，但不消耗识别重试额度。

总查询预算默认 120 秒，在阶段边界检查并传给常驻模型排队／加载／推理。冷指纹一次性进程和数据库等待仍有各自超时，不是严格 120 秒墙钟 SLA；一次性旧 OCR 不拥有常驻模式的按页调度能力。

本轮未改变分块、精度、识别分辨率、向量维度或近似索引；未跑客户全卷，不代表 OCR 准确率、全卷吞吐或父子块检索已验收。父子块后续接入时必须复验其依赖失效逻辑。

界面验证覆盖加载／空项目／部分覆盖原有路径、取消、恢复按钮、错误反馈和忽略迟到结果；通过生产 JS 的 Node DOM 夹具与 ASGI 接口执行。取消为原生文本按钮，状态区沿用 aria-live；本轮未执行真实浏览器视觉检查、移动端布局或屏幕阅读器端到端测试。
