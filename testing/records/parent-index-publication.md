## 接口与存储

`parent_index.ParentIndex` 内部流程为 prepare → register／StageJobs.claim → embed → publish。prepare 校验组装父块的原文、引用页、字符映射、依赖完整性及阅读顺序；生成不跨父块的子块，将原页 spans 与派生分隔符裁剪并平移到子块坐标。每批最多 20 父块／20 输入页／128 子块；父块仍受 4,000 字符／3 引用页约束，初始子块最多 700 字符、必要时重叠 80 字符。

`token_budget.LocalTokenBudget` 经独立检索环境的 tokenizer_worker 加载两套本地 tokenizer，不加载模型权重、不申请重模型许可。检查实际 token 数：Embedding 最多 4,096；重排按现有 Qwen 格式、空问题计算最多 2,048，另为至多 500 字问题预留 2,048。超预算子块有界二分，字符仍有映射；单字符也超预算时明确拒绝，不截断。最终完整重排入口仍重新检查 4,096 上限。其他模型／tokenizer 不能不经验证直接沿用该预留策略。

索引版本绑定组装／子块规则、Embedding 指纹及 tokenizer 运行配置。prepare 和 embed 在 SQL 事务外，空白就绪页可发布零子块且不调用 tokenizer／Embedding；非空未封口尾段不能假装零子块索引。所有输入未就绪时不登记向量阶段，应由后续组装调度保存缺口。

010 新增独立 parent_index_builds／parents／children／dependencies。父块存原文及映射；子块存原文、映射、实际 token 数及 1024 维向量。build 和子块 ID 确定且版本化；旧页级 indexed_pages／evidence_chunks 保留，未调整活动查询或默认后台流程。

## 发布和有效性

register 将精确 build、就绪源页、输入修订和版本绑定到阶段任务；publish 再比对 scope 与完整阶段 input_revision，不能借用其他策略的领取。StageJobs.complete 负责 parent／reading／升序源页／stage 锁、owner 和 run_epoch；回调在同一阅读锁下补验全部边界依赖，原子保存 build、全部父子、向量、依赖和阶段完成。任何插入失败全部回滚，可继续使用原已算向量重试。

同一 owner／代次重复投递幂等；错误 owner、旧代次、输入变更不能发布。即使旧阶段曾经 succeeded，resume 推进代次后也不能再以旧执行者重放发布成功。历史版本不覆盖旧引用。

metadata 只返回一个 build 的版本／父子数量／current，不返回正文；不是 06c 证据补读。current 同时核对现配置版本与所有来源／边界依赖；非首页变化、缺口补齐、页数缩小、模型变化都会使旧 build 不再合格。current 表示该独立索引成果的技术有效性，不表示已激活为应用检索索引。

清单 seal 仅用于内部对象意外变更检测，不是对外授权签名；后续 HTTP／MCP 不应直接接受任意完整发布清单，而应经项目绑定的服务入口生成。此次不增加对外 API。
