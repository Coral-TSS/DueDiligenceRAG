## 接口和行为

`assembly.py` 的 `PageSnapshot` 明确项目／材料／物理页／来源修订／文字／就绪状态／质量；`assemble(pages, state=None, final=False)` 返回封口父块和可 JSON 恢复的检查点。每批最多 20 连续页、200,000 字符，单页 100,000 字符；缺页须显式传快照，不能无声跳过。父块最多 4,000 字符／3 个引用页，段落目标 3,000 字符，未封口尾段最多 512 KiB。不同项目、材料或版本、跳页输入、损坏校验及封口后追加均明确拒绝。

原文字词、标点及内部换行保留；省略段首尾空白时仍按原字符坐标建立跨度。每个跨度记录原页起止和派生文字起止，新增段落分隔符单独列出。跨页只在前页逗号／分号和后页连接词同时存在时保守接续；不是只看有无句号。标题、独立表单（也包括前页表单）、疑似表格、质量未知、失败／待增强／缺页和空页均阻止强行续句。表格只保留原文，不猜列对应；没有实现 Docling 版面或通用表格恢复。

跨窗口不自动封口尾段；显式 final 才结束材料。超长条款按字符或页上限分为带 continuation_from 的续块，不生成摘要；ID 绑定策略、原文、spans、依赖及封口原因。仅用于边界判断的前瞻页／缺口也在 dependencies 中；`reverse_dependencies` 可以找到受引用或边界变化影响的父块。实际 tokenizer 复核属于后续子块／向量入口，本模块不把字符上限宣传为模型 token 安全保证。

## 持久化与并发

迁移 009 增加 assembly_checkpoints 和 assembly_batches；保存内部状态与历史批次 JSON 收据，不是正式父子块／向量表。`AssemblyStore.snapshots(..., ready_pages=...)` 要求调用者显式给出完成必要增强的就绪页，基础 OCR 成功不会自动变成最终可用页。页号和项目归属有边界。

`advance(..., expected_generation=...)` 在写事务外计算，短事务内核对阅读／源页及 generation，原子保存收据与下一检查点。重复同批请求可返回原收据；不同请求争用同代次只有一个成功。历史收据不是当前证据，重投前仍检查其依赖，不允许来源已变后直接复用。正文与修订号一起核对，伪造同修订正文不能保存。`restart` 是显式放弃旧尾段、保留历史并推进代次，不调用 OCR；它不能代替 06b 的局部增量重建。

缺失行无法加普通行锁，因此基础保存入口在 INSERT／UPSERT 前取得阅读共享锁；组装保存持阅读排他锁，阻止缺页在复验／提交之间插入。机器发布也先阅读后页，避免相反顺序。锁只在保存 SQL 内，不跨模型推理。直接外部 SQL 绕过仓储协议不受该约定保护。尚未连接阶段 owner／run_epoch，06b 集成时必须继续沿用 StageJobs 的父任务执行权保护，不能仅凭检查点 generation 替代旧执行者隔离。
