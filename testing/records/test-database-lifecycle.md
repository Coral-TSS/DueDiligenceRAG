## 实现

- `testing/support/database_lifecycle.py` 只持有本实例 CREATE 成功的 `dda_test_<32位UUID>`，名称改变时拒绝清理；不接收待清理库名列表，不扫描历史库。
- `testing/tests/conftest.py` 在 pytest teardown 报告生成时回收，此时应用、worker、连接池等 fixture 均已收尾。setup／call／teardown 任一失败均保留。
- 成功／跳过且没有连接的库使用普通 DROP；占用或并发新连接导致无法 DROP 时保留，不 FORCE、不终止后端。结果未知和集群已关闭也保留。
- 正常会话收尾可能先关闭集群，最后一个库留在该次运行目录，避免重连或重启集群。清理错误显式成为 teardown 失败，不吞异常。
- 每次操作追加 `database-lifecycle.jsonl`，仅库名、用例、动作、结果及必要的异常类型，不含 DSN 或凭据。
- 每个用例仍从空数据库迁移；原 fsync、连接等待、线程等待、SDK 等预算和业务断言保持不变。不清理历史目录或业务数据。
