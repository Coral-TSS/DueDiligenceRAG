# RG-05a：阶段计时与复用基线

更新：2026-10-26。RG-05a 阶段采集、复用统计和两页基线已完成。模型运行成功不代表识别质量达标，缓存／并行／父子分块等后续优化仍未实施。

## 实现与使用

- performance.py 提供嵌套阶段、计数、首次事件、控制异常分类及可选内存采样。操作／API 完成后写本地 JSON，明细上限 1,024 条；超出后仍累计总量。
- 覆盖预检、文字提取、渲染、OCR／视觉指纹和加载／推理、切块、Embedding 指纹和加载／推理、重排、SQL／连接、索引发布和 HTTP 实际字节；记录页面与候选复用数。
- 仅实际领取的任务创建 job 记录，空轮询不落盘。检查点／保存和任务年龄可观测；年龄含暂停时间，不等于纯排队耗时。现有模型锁非阻塞，只记录获取耗时和忙碌拒绝。
- index.first_searchable 只在非空片段提交后首次记录；空文本页／纯复用不制造首次发布时间，不代表整卷已可检索。
- 子进程统计消息不进入 OCR／向量业务结果。性能记录不含原文、查询、文件名、连接串或 SQL 参数；写入失败不替换业务结果／异常。
- 默认写配置数据目录的 performance/，DDA_PERFORMANCE_ENABLED=0 可关闭自动采集。测试输出均在 testing/runs/。

## 时间与内存口径

阶段时长存在嵌套／重叠，不能相加当总耗时。worker 包络包含启动、导入、协议等待及调用方消费流式结果的时间；模型加载／推理看各自子阶段。SQL execute 不含连接、提交及全部结果消费成本，完整发布看 index.publish；sql.fetched_rows 目前累计显式 fetchone／fetchall，游标迭代不计入此数。HTTP 字节为 ASGI 正文，不含请求／响应头。尚未实现的跨页组装不伪造时长。

status 表示操作控制流；被接口处理的 HTTP 错误看 http.status.*，已捕获的局部处理失败看页失败计数／业务返回，不能把 status=ok 理解为全卷内容质量正确。chunks.created 是生成的切片数，可能包含发布失败后重算，不等于数据库最终片段数。

普通记录中的进程 RSS 高水位是进程生命周期峰值，不是本次增量。基线另以 100ms 采样主进程与登记 worker 的同时点 RSS 总和，不能将各进程历史峰值相加；可能漏短峰，不含数据库或未登记辅助进程。

Windows 的 Popen.pid 可能是轻量虚拟环境启动器；worker 在加载模型前补报实际解释器 PID，采样同时跟踪两者，退出后移除。真实分配 128 MiB 的子进程测试验证此规则。

## 基线场景与复现

固定两页合成 PDF：默认两页原生文字；--models 为一页原生文字＋一页中文图片。样本生成脚本与 SHA-256 随记录保留。使用隔离 PostgreSQL／pgvector，不读取应用 .env 连接或客户卷宗。

场景为首次处理、成果复用、第 1 页保存后暂停／新服务对象继续、首次／重复查询和页面读取。真实模式运行本机 PaddleOCR、PaddleOCR-VL、Qwen Embedding 和 reranker；默认仅替换向量模型，PDF／SQL／发布仍真实执行。

首次处理不清空 OS 缓存；复用指持久成果命中，不表示模型常驻。两页样本不产生稳定 p95 或全卷吞吐／质量结论。硬件、依赖、模型、读取／索引版本及渲染配置随最终 summary.json 保存。

```powershell
.\.venv-dev\Scripts\python.exe testing\scripts\performance\baseline.py
.\.venv-dev\Scripts\python.exe testing\scripts\performance\baseline.py --models
```

输出：testing/runs/<run-id>/performance-baseline/summary.json 及逐场景 trace；测试库退出后停止。
