## 二、缓存键／目录／验证模式

- 目录：`cache/fingerprints/<kind>/<key[:32]>.json`、`cache/preflight/preflight/<key[:32]>.json`。
- 键 = SHA-256(kind + 运行时描述符 + 算法标记 + 全部参数 + 文件清单)。文件清单含路径、大小、`mtime_ns`、首尾各 64 KiB 抽样摘要；缺失文件记为 `missing`，不静默漏检。
- 运行时描述符 = 依赖 `dist-info` 名称（`torch`／`transformers`／`tokenizers`）+ `pyvenv.cfg` 摘要；**无法确定时返回 None，并强制完整复验**。
- 验证模式：`full`（本次完整重算）、`metadata`（命中此前完整校验过的条目）。**`metadata` 不等于内容哈希**：清单未变的原地改写无法由快检识别，因此保留 `verify=True` 严格复验入口，且它不被缓存短路。
- 写入：`.tmp-<hex>` + `os.replace` 原子替换；写失败只计数 `cache.write_failed`，不影响业务结果。内存层仅 64 项 LRU 加速，不是恢复依据。
- 三类摘要算法的位级结果未改变，reading／index 版本命名规则不变。

## 三、空输入（PF-08）

- 全空批：不启动 Embedding worker，直接发布零片段页状态（`indexed_pages` 含该页，无 `evidence_chunks`）。
- 混合批：空页直接发布，只有非空片段页进入模型；`requests` 不含空页。
- 零片段页计入覆盖计数但检索无命中；页级发布记录不等于存在可检索的实质文字。

## 五、真实模型复用基线对照

同两页样本、真实 PaddleOCR／PaddleOCR-VL／Qwen Embedding／reranker，`DDA_TEST_PERFORMANCE_MODELS=1` 运行 `testing/tests/test_performance_baseline.py`：1 passed，252.63 秒。产物：`testing/runs/baseline-rg05b2/performance-baseline/summary.json`。

| 场景 | RG-05a 基线 | RG-05b 后 | 说明 |
| --- | --- | --- | --- |
| 同版本成果复用 | 8.184 秒／112.9 MiB | **3.649 秒／87.6 MiB** | 四类缓存全部命中；OCR 调用 0，页读取／增强／索引复用均为 2 |
| 复用场景三类指纹 | OCR 0.225 + 视觉 4.131 + Embedding 2.772 ≈ 7.13 秒 | OCR 0.010 + 视觉 0.007 + Embedding 0.005 ≈ **0.022 秒** | 命中后不读取权重内容，`fingerprint.*.bytes` 为 0 |
| 首次处理 | 52.05 秒 | 89.34 秒 | 本次机器磁盘明显变慢（集群单次 checkpoint 写盘 302 秒），首次仍为全部未命中，不应与本项对比 |

说明：复用场景的收益来自指纹／预检阶段（7.13 → 0.022 秒）。首次与其他场景的绝对耗时受本次机器 I/O 退化影响（首次 52.05 → 89.34 秒），因此只用同场景的阶段计时与 `cache.hit.*`／`cache.miss.*` 计数作因果证据，不把整机变慢归因于本项。
