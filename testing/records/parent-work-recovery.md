2026-10-28。任务状态只维护 tasks.md。用户升级后只读 check 确认业务库 010 就绪；本轮新增 011，先仅在隔离库验证。此子范围不是整个 RG-06b 或默认后台启用验收。

## 交付

- 011 新增 parent_index_work：不可变准备清单、头部摘要、可选完整向量及对应摘要。一个工作包独立加载，沿用 12 MiB 清单应用上限，数据库另有存储大小保护；不读取全项目工作包正文。
- ParentIndex.register 在同一 parent 保护事务中验证来源、保存准备清单和登记阶段；失败一起回滚，同一 build 的不同清单不能覆盖。可传 expected_epoch，后台恢复登记时明确使用该保护。
- ParentWork.load 按 task／owner／当前 run_epoch 与材料绑定读取，验证清单／版本／阶段 scope 和全部来源依赖。模型指纹及大对象校验在事务外，短事务再做来源／领取复验。错误 owner、旧代次、来源／模型变化、清单或向量损坏均拒绝。
- save_vectors 在原领取下受保护保存完整向量检查点；失败回滚且不误完成阶段。已存结果只允许相同结果重投，不能被另一次计算覆盖。最终 ParentIndex.publish 也核对持久清单与已存向量的一致性。
- run 加载工作包，缺向量时才 Embedding，先保存向量再响应安全点暂停／停机／单阶段暂停，随后最终发布。已有向量时不再 tokenize 或 Embedding。资源繁忙归还领取并延后，不增加 failures。
- requeue 需明确继续后的 expected_epoch；从已有工作包重新登记到新代次，源／模型过期则拒绝，不重新 OCR。已成功阶段可由 StageJobs 返回 reused，调用者按已有成果处理，不应再次领取。

JSONB 会把 -0.0 规范为 0.0，已通过真实失败用例确认其可导致摘要伪损坏。ParentIndex.embed 在生成摘要前统一零值表示，非零模型数值与推理精度不变，维度仍为 1024。
