## 统一实现约束

### 查询与数据库

1. 模型指纹检查／加载／推理、文件读写均不得放在持有页面写锁的事务中。搜索先做轻量范围核对与短快照，再在事务外生成向量；召回、发布／返回前校验分别为短事务。仅靠缩短事务不能取消最终版本验证。
2. 连接池初始容量须计入后台 worker、短 HTTP 请求和保留的队列租约连接，设置等待超时与总上限。会话级 advisory lock 的专用连接必须显式释放／销毁；测试两个进程竞争，不能把锁泄漏给下一位借用者。CLI 使用后正确关闭池，不让进程挂起。
3. 定位单页、最新机器结果、候选缓存、任务最新状态等查询用明确字段和范围；根据隔离测试库的 EXPLAIN (ANALYZE, BUFFERS) 决定索引。vision_candidates 的当前迁移只有主键，优先评测按材料／页／版本／状态查最新候选的索引；不在 JSON 正文上盲目增加大索引。
4. 批量写入优先比较 executemany／驱动批处理与逐条写；仅大批收益成立时考虑 staging＋COPY。保持父块事务原子性和逐页 OCR 耐久性，不关闭 fsync 或减少必要提交来制造速度收益。
5. 当前发布锁住材料读取版本是正确性保护，移除前必须定义版本锁与多页依赖的一致性协议。涉及多个页时统一锁顺序，避免并发发布死锁。
6. 覆盖缓存可稍后刷新但必须标注统计修订／时间；搜索正文的来源有效性不得仅凭 TTL。源页、机器有效文字、分块配置和新索引发布都要触发相关修订。若缓存完整查询结果，新材料加入必须令其失效。RG-05i 当前仅缓存查询向量与重排分数，不缓存整份结果；每次重新召回、来源复验和覆盖聚合，以此保证新材料立即可见。

### 页面与请求

- 进度接口只返回阶段计数、执行位置、资源等待、简短错误和修订标识；失败页清单单独分页，响应不随已处理正文／历史条数增长。
- 阅读器先取有界页目录，选中页再取正文；行框、机器历史、视觉历史按需读取。任务位置变化不自动重取未变正文；新页目录增量更新，保持用户当前页与滚动位置。
- 条件请求／内容版本键防止重复下载；图片版本与当前图像修订关联。对正文缓存命中也须校验版本，不能用过期图片配新 OCR 行框。
- 前端有且只有一条活动轮询链，页面隐藏时退避、回到前台立即核对；失败指数退避并有上限。切页／切项目取消旧请求并保留代次检查。已有 generation 只防旧响应覆盖，不会停止已发请求的成本。
- 同步搜索请求当前会占用服务线程直到模型结束；跨客户端并发须有入口限额和有限队列，不能靠增大 HTTP 线程池掩盖模型瓶颈。前端 Abort 不等于服务端计算取消，服务端取消／超时须和 worker 请求标识关联，在安全点丢弃结果、释放资源。首版可返回明确忙碌与重试提示，等待不能无上限。
- 材料分页、单页读取先行落地；独立覆盖页再接入 RG-02。无需为了轮询优化引入 WebSocket 或新中间件。

### 模型与计算资源

- 每个持久 worker 有请求 ID、当前模型版本、ready／busy／failed 状态和待办上限；加载后可处理多个请求，异常后销毁实例并有限重启。设置加载／单请求／空闲超时，迟到结果不能交给下一请求。
- 视觉、Embedding、reranker 按活动模型预算复用；不默认同时常驻。查询优先在区域／微批边界调度，不中途强杀有效页推理；后台保证有进展的份额。轻量 SQL／正文补读不占推理令牌。
- 基础 OCR 内部线程、PyTorch 线程、进程数共同计入 CPU 预算。oneDNN（`enable_mkldnn`）仍默认关闭：它是当时的 CPU 基线，且 Windows 上 Paddle 3 的 oneDNN 曾无法执行部分原语。只有 `DDA_OCR_ENABLE_MKLDNN=1` 且实际走 CPU 时才打开；GPU 不传该参数。精度和设备见 [GPU 安装](../due-diligence-agent/gpu-setup.md)，不把设备写进已完成页的版本。
- 子块按实际 token 长度分桶、限制最大条数与总 token／像素预算；批内错误可拆分重试但有次数上限。保存每条输出归属，完整父块验证通过才发布。空输入不启动模型。
- 缓存区分预检／权重指纹、图像、查询向量、子块向量、重排分数与完整结果。文本向量键包含模型、tokenizer／池化／指令、精度／后端及输入摘要；重排另含 query、候选文本和 reranker 版本。缓存有容量、逐出与损坏处理，数值输出重新验证；缓存服务失败不能导致错用旧证据。
- 模型指纹不能只信目录名或永久信任 mtime。以验证过的权重清单和受控激活版本为基础；元数据用于快速检测，替换模型需重新内容校验。需要检测元数据完全不变的替换时仍须完整校验，不能声称元数据检查与内容 hash 等价。

### 图像、磁盘与历史

- 文字页原生提取先完成，预览按需渲染。扫描页识别图与低分辨率浏览缩略图分离；不得为了浏览提速降低 OCR 输入质量。模型裁剪坐标必须对应正确方向与图像版本。
- 基础 PDF 图像若已生成且版本相同，OCR 后续失败可复用渲染成果；需要在阶段表中记录该成果，不能靠扫描目录猜测完整状态。同页区域识别可复用一次解码，但限制缓存图片数量／总像素。
- 上传当前 UploadFile 可能在 multipart 层暂存后再由 Storage 流式保存，存在额外磁盘读写；这是代码路径推断，实际落盘由大小和运行环境决定。先测上传耗时、临时空间峰值，不先重写上传协议，不删除流大小限制、摘要、fsync 或无覆盖发布保护。
- 对原件、基础成果、当前／历史证据依赖的图像和版本保持引用；可清理范围仅为确认无引用、未被活动任务使用的临时缓存。先提供磁盘清单／dry-run，再实施带保留期的回收；本次文档调整不执行清理。
- 普通运行日志按大小／数量轮转，测试运行产物仍进入 testing/。检索临时目录删除前保留不含客户正文／凭据的错误类别和阶段指标，不为诊断永久复制所有请求载荷。
