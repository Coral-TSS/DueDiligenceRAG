## 1. 业务目标

尽调人员按项目工作。每个尽调项目以后各自形成报告；本仓库只负责该项目的材料、处理和证据。一个项目下可以有很多份材料，类型和文件格式不必相同。每份进入解析范围的材料都要能解析，并按自己的来源位置向量化入库。

项目 A 和项目 B 的材料没有业务关联。检索、补读、引用、缓存命中和任务状态都不能把 A 的内容带到 B，也不能把 B 带到 A。

项目是工作区范围，不是多租户身份。本机同一操作者可以列出并进入各个项目。换项目靠显式的当前项目，不靠登录角色。

## 2. 用户流程

1. 打开项目列表。没有当前项目时，只显示列表和创建入口。
2. 用户创建项目，或点选已有项目。这一选择成为当前项目，并出现在工作台、处理进度、检索和补读地址里。
3. 在工作台导入该项目的材料，查看每份材料的登记、解析、失败和可检索范围。
4. 从同一当前项目进入证据检索。检索只提交这个项目。用户可以再缩小到某些材料或来源位置；缩小范围不能取消项目边界。
5. 从命中结果补读原文。补读地址带项目、材料、证据或来源位置以及版本。
6. 切换到另一个项目时，材料列表、进度、检索结果、补读正文和尚未画到页面上的旧响应都换成新项目或被丢弃。刷新后仍是切换前显式选中的项目；没有显式选择时，刷新不替用户挑一个项目。

没有当前项目时，不发起检索，也不按“最新创建的项目”或全库搜索。

空项目、正在加载、加载失败、部分处理、处理完成、检索无命中、检索有候选，各自有可区分的说明。部分处理不能显示成整份材料已可检索。无命中不能显示成材料不存在。

## 4. 非目标

- 不实现报告生成、尽调 skill、工作文件编辑或法律结论。
- 不把项目隔离做成多租户账号、项目成员或对外网关。
- 不按项目拆物理数据库、schema 或向量 collection。独立物理库只在将来出现互不信任的数据库账号，且应用层条件不足以满足删除、备份或加密边界时再单独立项。
- 不在未经另行确认时提供删除项目、删除材料或清空向量。
- 不把 `.doc`、`.xls`、`.ppt`、带宏文件、密码或加密文档、以及 LibreOffice／Office 转换写成首批能力。
- 不因为文件能被登记，就宣称该格式已解析、已向量化或已有原生页码。
- 不用检索相关分数、mock 向量或单元测试通过，代替 OCR、视觉或检索质量验收。
- 不把 RG-06 的“只搜某一份材料或某几页”写成跨项目隔离的替代品。过滤是在当前项目之内再缩小。

## 5. A. 项目中心页面

工作台是当前项目的材料与进度。检索和阅读页使用同一个当前项目标识。材料清单继续按项目分页，不一次装入全部正文。

处理进度至少区分：尚未预检、解析或识别进行中、部分完成、失败可重试、当前版本可检索、来源变化后待重建。搜索结果上已有的简要页数比，不能代替这份进度。完整缺口清单的字段以 RG-02 为准，页面放在当前项目工作台，而不是全库仪表盘。

检索页沿用现有两类结果：页级片段，以及父块命中和有界上下文。补读沿用版本绑定；过期引用保持过期，不自动换成新正文。

### 验收

- PC-A01：项目列表可创建并在重启后看到。空白或超长名称失败，且不改变已有当前项目。
- PC-A02：当前项目只来自用户的创建或点选，并写入可刷新保留的位置（建议地址参数）。已有项目时，不把创建时间最新的一项设为当前项目。
- PC-A03：无当前项目时，工作台不展示任何项目的材料，检索不能提交，页面不请求 `POST /api/projects/{id}/search`。
- PC-A04：工作台、处理入口、检索和阅读链接使用同一个项目标识。从工作台进入检索时，检索的项目与工作台一致。
- PC-A05：切换项目会清空材料、进度、命中和补读，并丢弃晚到的上一项目响应。上传或检索进行中切换时，结果仍记在发起时的项目下，不画进新项目。
- PC-A06：空、加载、失败、部分处理、可检索、无命中、有候选的文案可以彼此区分。失败可以重试。部分成功保留已成功项。
- PC-A07：数据库未就绪时页面仍能打开并说明配置动作，不显示连接密码。

## 6. B. 业务类型与文件格式

业务类型和文件格式分开。

业务类型表示尽调里的材料种类，例如营业执照、章程、决议、财务报表。它不由扩展名决定，也不能从旧报告答案反推。首批格式解析不要求自动判断业务类型。自动分类若要做，单独确认，并且不确定时标成未分类，不阻塞解析。

文件格式表示字节如何读取。登记、解析、来源位置和向量化是四步。登记成功只说明文件已保存。

| 格式 | 2026-11-07 已核对的实现 | 规格里的长期要求 | 本增量建议 |
| --- | --- | --- | --- |
| PDF | 已登记、预检、原生文字、OCR、视觉、页切片、父子块和检索 | 继续作为扫描／混合档案主路径 | 保持。不把 PDF 页码模型套到其他格式上 |
| PNG／JPEG | 独立图片不是当前解析链。PDF 内页面图可以预览 | 首版材料范围包含图片 | 仍后置。不在首批 Office 里夹带 |
| DOCX | 非 PDF 会登记为“暂不支持”，不解析。`pyproject.toml` 无 python-docx | 可读段落和表格原生提取；整份 Word 不默认转图片。参考报告 DOCX 不是证据适配器 | 建议作为首批第一种现代格式，待确认 |
| XLSX | 未解析。无 openpyxl | 单元格来源准确；公式与缓存值分开 | 建议紧随 DOCX，待确认 |
| PPTX | 未解析。无 python-pptx。由 PPT 导出的图片 PDF 才走 PDF 链 | 关键事实能回到稳定位置 | 建议作为首批第三种，待确认 |
| DOC／XLS／PPT | 未做原生解析，也没有转换器 | 必须明示不支持或转换方式，不能静默跳过 | 首批明示不支持。不引入转换进程 |
| 宏、密码、加密包 | PDF 加密在预检阶段说明。Office 加密包没有解析器 | 不能当成已读正文 | 登记为无法解析并说明原因。不尝试猜密码或执行宏 |

建议的首批顺序是 DOCX，然后 XLSX，然后 PPTX。这是建议，不是已排期的实施。用户若要改顺序或只做其中一种，以确认结果为准。三种都确认前，不添加对应依赖，也不把上传状态改成“待解析”。

### 6.1 首批可行边界

DOCX 只读取正文段落和表格单元格里的可见文字。保留段落序号；表格保留表序号、行、列和单元格内段落。页眉页脚、批注、修订、文本框、公式对象和嵌入对象首批不当作正文。嵌入图片只记“此处有图、未提取”，不假装已经 OCR。不生成 Word 排版页码。

XLSX 只读取工作表中已经缓存的单元格显示值。来源是工作表名、行号和列号。公式与缓存值都存在时，入库文字用缓存值，并标记该格含公式、本系统没有重算。只有公式、没有缓存值时，该格标未知，不把公式文本当成计算结果。隐藏表、数据透视缓存、宏表和外部链接不纳入首批正文。

PPTX 按幻灯片序号读取形状中的段落文字。来源是幻灯片序号、形状序号和段序号。备注页、母版、动画和演讲者备注不在首批，除非以后单独确认。不把幻灯片序号写成 PDF 页码。

这三类都不进入现有 PDF 的跨页组装窗口。它们使用自己的来源单元切块和向量化。父子块若要跨段落或跨幻灯片，另立任务，不能复用“PDF 第 N 页”的父块。

### 6.2 来源位置

对外位置使用带种类的定位，而不是单一页码。

| 种类 | 必须标出的位置 | 禁止的呈现 |
| --- | --- | --- |
| PDF | 物理页码，加上页内字符或已有 source span | 把未渲染的 PDF 说成 Office 页 |
| DOCX | 段落序号；表格再加表、行、列 | “第 N 页”，除非将来有单独记录的渲染版本 |
| XLSX | 工作表、行、列 | 把行号叫页码，或把公式当取值 |
| PPTX | 幻灯片、形状、段落 | 把幻灯片叫 PDF 页 |

预览、检索标题、补读和 MCP 返回使用同一种定位。原件下载仍按项目和材料标识，不按文件名拼路径。

### 6.3 入库、失败、重试、重复上传

每个来源单元独立成功或失败。一份材料里一个表失败，不撤销同文件已经发布的其他单元，也不阻塞同项目其他材料。失败记录原因，并允许只重试失败单元。同一来源版本和同一索引版本下，未改动的单元不重新嵌入。

同一项目、相同字节重复上传，仍是一条材料，并保留多个来源文件名。不同字节即使同名，也是另一条材料。另一个项目上传相同字节或相同文件名，是另一条材料、另一份文件和另一组向量。解析失败不把材料登记成已索引。

旧索引版本可以留在库里，当前检索只用与当前解析版本和模型版本匹配的单元。版本不一致时该单元待重建，不把旧文字混进新结果。

### 验收

- PC-B01：业务类型字段与扩展名无关。首批可以没有自动分类；未分类不等于解析失败。
- PC-B02：PDF 现有登记、阅读、检索和页码引用保持可用。
- PC-B03：在对应格式被确认实施之前，DOCX／XLSX／PPTX 保持明确的“暂不支持”，不出现伪页码结果。
- PC-B04：确认实施的格式能从合成文件抽出约定文字，并带回上表的定位。表格单元格能回到表、行、列。幻灯片文字能回到幻灯片和形状。
- PC-B05：XLSX 公式在没有缓存值时不可检索为计算结果；有缓存值时结果文本与“未重算公式”标记同时存在。
- PC-B06：DOC／XLS／PPT、加密或宏文件被拒绝或标成无法解析，原因可见，不调用外部转换器，不执行宏。
- PC-B07：非 PDF 命中的标题、链接和补读不使用“PDF 第 N 页”。
- PC-B08：同项目相同内容重复上传不新增材料、不重复向量。同项目同名不同内容分开。跨项目相同内容分开。单单元失败可重试且不删除其他单元的已发布向量。

## 7. C. 项目隔离

继续使用一个 `dd_agent` schema 和现有向量表。每个对外读、写、检索、补读和任务操作都带项目标识，并在服务层再次核对材料属于该项目。只在 SQL 或缓存键里漏掉项目条件，视为未完成，即使页面下拉框选对了项目。

向量支、关键词支、RRF 融合、重排、父块召回、父块补读、页补读、模型结果缓存和 MCP 都使用这次请求的项目。缓存可以按项目分开保存同一段查询文本的向量，但不能把另一项目的切片当作命中。

材料过滤和页过滤只减少当前项目内部的候选。它们不是隔离机制。

### 验收

- PC-C01：A、B 都有同名不同内容的文件时，列表、下载、进度和检索只出现本项目那一条。
- PC-C02：A、B 都有相同字节并都已索引时，向量、关键词、hybrid 和父子混合在查询 A 时只返回 A 的材料标识。查询 B 对称。
- PC-C03：用 B 的项目标识读取 A 的材料、页、预览图、父块、证据标识、任务或目录游标时，返回不存在或不属于当前项目，响应里没有 A 的正文和存储键。
- PC-C04：MCP 的列表和检索必须带项目。用 A 的项目加 B 的材料标识检索会被拒绝。省略项目标识不会搜索全部材料。
- PC-C05：A 的处理任务在排队或运行时，B 的进度和覆盖看不到 A。用 B 的路径暂停、继续或控制 A 的任务被拒绝，A 的任务状态保持不变。
- PC-C06：A 上相同查询命中过模型缓存后，B 的检索结果仍只含 B 的切片。相同内容不合并两项目的向量行。
- PC-C07：无当前项目时不存在默认全库或默认最新项目的检索。

## 9. 验收方式

工程验收使用合成文件和独立测试库，断言用户可见的状态、标识和正文边界。浏览器或现有前端脚本验证页面流程。

真实模型、真实 GPU 和客户整卷另列。没有这层记录时，不写 OCR 正确率、检索质量或全卷耗时已经达标。

用户确认本文之前，不把其中任何一条 PC 验收标成实现完成。
