## 1. 业务目标

尽调人员（及后续只读 Agent）在当前项目里，不只靠文件名认出材料。每份材料可以标明：材料类别、所属主体、日期或期间。检索与材料列表可以按这些字段缩小范围，也可以按材料标识与 PDF 页范围缩小。未填写类别的材料仍可解析和入库；有过滤条件时，未匹配的材料默认不出现在结果里，并提示有多少份因此被排除。

材料都是律师已收集好的。本增量不判断材料本身是否可信，也不做版本、签署、关联材料、填写人或标签备注一类管理字段。

项目仍是硬边界。主体与元数据都属于某个项目；用 A 的主体、材料或过滤条件去查 B，必须被拒绝。

## 2. 用户流程

1. 打开当前项目工作台。材料列表除文件名与处理状态外，显示类别、所属主体、日期或期间；未填的显示为「未分类」或「未填写」。
2. 对单份材料打开编辑：选择类别、选择或新建本项目主体、填写签署／出具日或报表期间，保存。
3. 可对多份材料批量设置同一类别、同一主体或同一日期／期间；批量不覆盖用户未勾选的字段。
4. 进入检索页。除查询正文外，可勾选材料、页范围（仅 PDF）、类别、主体、日期／期间。提交后只在当前项目内、且满足全部已设过滤条件的候选中召回。
5. 无命中时说明是过滤后无结果，并给出因未分类／未填主体／未填日期而被排除的份数（若本次过滤用到了对应字段）。不把「无命中」说成「项目里没有材料」。
6. MCP／Agent 用 `list_documents` 看到同样的元数据，并可按相同字段筛选；用 `search_evidence` 传入相同过滤参数。省略新参数时行为与现网兼容。

空列表、加载中、保存失败、过滤后无命中、有候选、跨项目拒绝，各自有可区分说明。

## 4. 三类元数据

### 4.1 材料类别

固定类别表。取值与文件扩展名无关，也不能从旧报告答案反推。缺省为「未分类」。未分类不等于解析失败，不阻塞登记、阅读、向量化。

默认清单（2026-11-09 用户确认采用）：

| 代码 | 显示名 |
| --- | --- |
| `uncategorized` | 未分类 |
| `business_license` | 营业执照 |
| `articles` | 公司章程 |
| `shareholder_resolution` | 股东会决议 |
| `board_resolution` | 董事会决议 |
| `equity_structure` | 股权结构／名册 |
| `audit_report` | 审计报告 |
| `financial_statement` | 财务报表 |
| `major_contract` | 重大合同 |
| `litigation` | 诉讼／仲裁文书 |
| `ip_certificate` | 知识产权证书 |
| `regulatory_filing` | 监管报送／批复 |
| `hr_labor` | 劳动／人事材料 |
| `other` | 其他 |

每份材料一个类别。不允许自造未在表中的代码；未知代码拒绝保存。

### 4.2 所属主体

主体属于项目，不跨项目共享。一个项目可有多个主体，例如目标公司、子公司、股东、交易对手。主体至少有显示名称；可选角色标签（目标公司／子公司／股东／交易对手／其他），角色不是权限。

每份材料至多绑定一个所属主体。未绑定显示为「未填写」。首批只允许改名，不提供删除或停用。若以后要删，须另改规格（引用中的材料如何处理一并定）。

跨项目：用项目 A 的主体标识写入项目 B 的材料，或在查 B 时过滤 A 的主体，一律拒绝，响应不含对方名称正文以外的泄露（错误只说不存在或不属于当前项目）。

### 4.3 日期或期间

两种互斥表示，另加未填写：

| 种类 | 含义 | 字段 |
| --- | --- | --- |
| 未填写 | 缺省 | 无日期 |
| 时点 | 签署日、出具日、生效日等单一日历日 | 一个 `YYYY-MM-DD` |
| 期间 | 报表期间、审计覆盖期等 | 起日与止日，起 ≤ 止 |

不存时分秒，不存时区；按日历日理解。非法日期、起大于止、时点与期间同时有值，拒绝保存。

## 5. 数据模型（建议迁移 019）

不在本文写 SQL。实现时新增迁移文件，健康检查版本进到 19。字段与约束如下。

### 5.1 项目主体

建议表 `project_subjects`（名称可在实施方案里微调）：

- `id` UUID 主键
- `project_id` UUID 非空，外键 projects，索引
- `name` 文本，去首尾空白后长度 1–200
- `role` 文本，取值有限集合（含 `other`），缺省 `other`
- `created_at` 时间戳
- 同项目内名称大小写不敏感唯一（或规范化唯一键），避免重复主体

主体行必须带 `project_id`。没有「全局主体」。

### 5.2 材料上的元数据

挂在现有 `documents` 上（同项目、同 sha256 仍是一条材料）：

- `category` 文本非空，缺省 `uncategorized`，取值 ∈ 固定类别表
- `subject_id` UUID 可空；非空时必须引用同项目 `project_subjects.id`
- `date_kind` 文本非空，取值 `none`／`point`／`period`，缺省 `none`
- `point_date` 日期可空；仅当 `date_kind=point` 时非空
- `period_start`／`period_end` 日期可空；仅当 `date_kind=period` 时均非空且 start ≤ end

约束：`subject_id` 所属项目 = 材料 `project_id`（应用层必查；数据库可用复合外键或触发器，实施方案决定）。`document_sources`、sha256 去重、存储键规则不变。

### 5.3 列表与目录投影

`material_catalog`、工作台材料列表、MCP `list_documents` 在现有字段之外增加：`category`、`subject_id`、`subject_name`（可空）、`date_kind`、`point_date`、`period_start`、`period_end`。仍不返回存储键、原件路径或正文。

## 6. 页面录入与批量编辑

### 6.1 单份编辑

工作台每行可打开「材料信息」。表单：类别下拉、主体下拉（可跳去新建主体）、日期种类、时点或起止日。保存成功后列表即时更新。校验失败指明字段。并发：后写覆盖前写；不在首批做乐观锁，若以后要做另立任务。

### 6.2 批量编辑

多选材料后设：类别、主体、日期／期间中的任意子集。未勾选「改类别」则不改各类别；主体与日期同理。批量提交是一个项目内操作；任一条不属于当前项目则整批拒绝，已成功条不部分提交（首批采用全有或全无）。

### 6.3 主体管理

在当前项目下创建主体（名称必填、角色可选）。列表仅本项目。首批只允许改名，不提供删除。新建主体后可立即用于材料绑定。

### 6.4 与解析的关系

改元数据不触发重新解析、不改向量版本、不改文件名。第一版不做自动分类。若将来要做自动建议：只能建议，不确定则为未分类，且永不阻塞解析——须另开任务并改规格后才能开工。

## 7. 过滤语义（RG-06 扩展）

### 7.1 总则

1. 先强制当前 `project_id`，再应用过滤。
2. 不同字段之间为 **AND**（材料范围 ∧ 页范围 ∧ 类别 ∧ 主体 ∧ 日期）。
3. 同一字段多值为 **OR**（例如类别∈{章程,决议}；材料标识∈{id1,id2}）。
4. 未出现的过滤字段表示「不限制该维」。
5. 空数组与「未传」区分：未传＝不限制；显式空数组＝无效请求（422），避免误当成全项目。
6. 过滤在 SQL／召回层完成，不在重排后再按 Python 循环剔页；禁止按命中逐条再查元数据的 N+1。
7. 材料标识、主体标识必须属于当前项目，否则整次检索失败（与现网跨项目材料标识一致：拒绝，不含对方正文）。

### 7.2 材料标识

允许多个 `document_id`。召回候选的材料集合 ⊆ 给定集合。MCP 现有单字段 `document_id` 保留；新增多值时须向后兼容（见 7.7）。

### 7.3 PDF 页范围

参数：`page_from`、`page_to`（含端点），1-based 物理页码，且 from ≤ to。

- 只约束带物理页码的命中（PDF 页级／父块子块上的页码）。
- **没有物理页码的 Office 来源单元：在「已设置页范围」时不进入结果。**（2026-11-09 确认）
- 仅指定页范围、未指定材料时：全项目中页码落在范围内的 PDF 命中可返回；Office 命中排除。
- 页码超出该材料实际页数：不报错，只是无该页命中。
- 对纯 Office 材料又只给页范围：结果可为过滤后无命中，并说明页范围不适用于无页码材料。

本迭代不做 Office 来源定位过滤（段落号、单元格、幻灯片号）。需要按 Office 缩小范围时，靠材料标识／类别／主体／日期，不靠页码，也不得把幻灯片号或行号写成 `page_from`／`page_to`。若以后要做定位过滤，须用显式定位参数另立任务，不得复用页码字段。

### 7.4 类别、主体

`categories`：代码列表，OR。`subject_ids`：主体 UUID 列表，OR。材料的 `category`／`subject_id` 必须命中。

**有类别过滤时，`uncategorized` 默认不匹配**（除非调用方显式把 `uncategorized` 放进 `categories`）。
**有主体过滤时，未绑定主体的材料不匹配。**

### 7.5 日期／期间匹配（重叠）

一律按下列重叠规则匹配（2026-11-09 确认），不按材料「仅时点／仅期间」种类另加限制。过滤可给：时点，或期间 `[filter_start, filter_end]`。

| 材料 | 过滤时点 D | 过滤期间 [Fs, Fe] |
| --- | --- | --- |
| 未填写 | 不匹配 | 不匹配 |
| 时点 P | P = D | Fs ≤ P ≤ Fe |
| 期间 [Ps, Pe] | Ps ≤ D ≤ Pe | 区间重叠：Ps ≤ Fe 且 Pe ≥ Fs |

有日期过滤时，未填写日期的材料默认排除。结果旁路字段给出：`excluded_uncategorized`、`excluded_unsubjected`、`excluded_undated` 计数（只统计「因该维过滤而被排除、且本请求确实启用了该维」的当前项目材料数；未启用的维为 0 或不出现）。

### 7.6 列表筛选

`list_documents`／材料目录支持与检索相同的类别、主体、日期过滤（不含页范围；页范围只对检索有意义）。分页仍按项目内键集，过滤在 SQL 的 WHERE 中完成。

### 7.7 MCP 与 HTTP 兼容

| 入口 | 现状 | 本增量 |
| --- | --- | --- |
| HTTP `POST .../search` | 仅 `query` | 增加可选过滤字段；旧客户端只传 `query` 行为不变 |
| MCP `search_evidence` | `project_id`、`query`、可选单个 `document_id` | 保留 `document_id`；增加可选 `document_ids`、`page_from`／`page_to`、`categories`、`subject_ids`、日期过滤。若同时传 `document_id` 与 `document_ids`，返回 422（2026-11-09 确认，避免歧义） |
| MCP `list_documents` | 仅 `project_id` | 返回元数据；增加可选筛选参数；只传 `project_id` 仍列出全项目材料 |

工具描述须写明：结果是候选证据；过滤后无命中 ≠ 材料不存在。

## 8. 状态与错误

| 场景 | 期望 |
| --- | --- |
| 加载材料列表／主体 | 区分加载中与空项目；空项目提示导入材料或创建主体 |
| 保存元数据校验失败 | 字段级错误，不清空其他已填项 |
| 主体不存在或不属于项目 | 404／业务错误「不存在或不属于当前项目」，无另一项目名称列表 |
| 检索无当前项目 | 与 PC-A03 一致，不发起搜索 |
| 过滤后无命中 | `status=no_matches`（或同等），带排除计数；文案区分「项目无索引」与「过滤过窄」 |
| 非法页范围、空数组、未知类别代码 | 422，可理解原因 |
| 数据库未就绪 | 页面可打开并说明配置，不显示密码 |

## 9. 非目标

- 可信度类：来源渠道、是否签署、版本／最终稿、关联材料、真伪判断。
- 管理类：填写人、置信度、自由标签、备注字段（主体改名以外的审计日志另议）。
- 自动业务分类／从文件名或正文推断类别（可另确认；默认人工）。
- 用元数据过滤代替项目隔离。
- 按项目拆物理库。
- 删除项目／材料／清空向量（仍按既有非目标）。
- 把 Office 幻灯片号、Excel 行号写成 PDF 页码。
- 在重排之后用应用层循环做过滤，或对每个命中单独查元数据。
- 报告生成、Harness 编排、法律结论。

## 10. 已确认决定（2026-11-09 用户）

原开放问题全部按下列口径定稿，实施不得另行猜测：

1. **类别清单**：采用第 4.1 节默认表，本迭代不增删合并。
2. **自动分类**：第一版不做。仅页面单份／批量人工填写。若以后要自动建议，另开任务；不确定→未分类，且不阻塞解析。
3. **`document_id` 与 `document_ids` 同时传入**：直接 422，不静默并集。
4. **主体删除**：首批只改名，不提供删除。删除与引用处理若要做，另改规格。
5. **Office 来源定位过滤**：不在本迭代。设页范围时排除无物理页码的命中；Office 靠材料／类别／主体／日期过滤。
6. **日期过滤**：一律按第 7.5 节重叠规则，不按材料日期种类另加限制。

## 11. 验收

- MM-01：材料可保存类别、主体、日期／期间；缺省未分类／未填写；非法值拒绝。
- MM-02：未分类材料可完整解析与检索；改元数据不触发重嵌入。
- MM-03：同项目多主体可创建；材料绑定后列表与 MCP 可见名称。
- MM-04：批量只改勾选字段；跨项目材料标识整批拒绝。
- MM-05：A 的主体不能写入或过滤 B；错误不含 B／A 对方正文。
- RG06-01：HTTP 与页面可按材料多选、PDF 页范围过滤；结果材料均属当前项目。
- RG06-02：类别／主体／日期过滤为字段间 AND、字段内 OR；未填维在启用该过滤时默认排除，并返回排除计数。
- RG06-03：页范围不作用于无页码 Office 命中；不把幻灯片当页码。
- RG06-04：MCP 旧参数集仍可用；新参数按本文；跨项目标识拒绝。
- RG06-05：过滤在召回 SQL 完成；同材料多命中不导致按条数的元数据 N+1（实现审查或查询计数断言）。
- RG06-06：过滤过窄的无命中与「未索引」文案可区分。

第 10 节已确认，不等于上述验收已实现。实现完成只记在 [tasks.md](./tasks.md)，不得把规格确认写成工程完成。
