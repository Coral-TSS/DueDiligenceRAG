# 项目中心实施方案

日期：2026-11-07  
状态：待规格确认后的实现方案。本文件不记录任务进度。进度只写 [tasks.md](./tasks.md)。行为以 [规格](./project-center-spec.md) 为准，测试顺序以 [测试设计](./project-center-test-design.md) 为准。

本轮不改 `src/`、`testing/` 或迁移。下面的文件是将来实施时的落点。

## 1. 技术方案

保留一个 PostgreSQL schema `dd_agent` 和现有 `evidence_chunks`、`parent_index_children` 向量表。项目隔离继续靠每次请求的 `project_id`：路由、服务层归属检查，以及召回 SQL 里现有的 `CURRENT`／`LIVE` 条件。不为每个尽调项目建库、建 schema 或建向量 namespace。

页面把当前项目放进地址。工作台、检索和阅读共用这个值。没有该值时不选择列表中的第一项，也不发检索。这只是工作区选择，不增加用户账号。

文件格式分成两套来源，不共用“PDF 页”这个对外字段：

- PDF 继续走 `document_pages`、`indexed_pages` 和已有父子块。
- 确认纳入的 DOCX／XLSX／PPTX 使用独立的来源单元。单元保存定位种类和坐标，再切片、写词项和 1024 维向量。它们不进入 PDF 跨页组装，也不把幻灯片或行号写进 `page_number` 后当成 PDF 页展示。

检索在项目条件之内合并 PDF 候选和新格式候选，再沿用一次 RRF 和一次重排。补读按定位种类分支。MCP 只增加只读工具，工具参数必填项目。

报告编排不在本方案内。对接验收只调用已经存在或按 RG-03 新增的只读 MCP 工具。

## 3. 数据与兼容

现有材料行、页、切片和父块保持不动。PDF 的 `(project_id, sha256)` 去重、按项目存储键和按页发布保持原语义。

来源单元若需要新表，建议字段至少包括：材料标识、定位种类、稳定坐标、文本、解析版本、索引版本、失败原因。向量行通过材料标识回到 `documents.project_id`，召回 SQL 与 PDF 一样带项目条件。不在切片上省略这条连接。

可以稍后把 `project_id` 冗余到向量行上做约束。那不是隔离正确的前提，而是防止以后的 SQL 漏掉连接。它会重写大表，单独评估锁和回填，不放进页面或隔离回归这一期。

旧客户端仍可使用 PDF 的 `page_number` 和现有父块 URL。新格式响应增加定位对象；缺少定位种类时，页面按 PDF 处理，从而不误标旧数据。

处理队列仍是本机一把执行锁。新格式的解析任务照旧带 `project_id` 和 `document_id`。不新增第二套队列。

## 4. 格式边界如何落地

解析器只接受 OOXML 压缩包。读取失败、加密包和宏项目给出材料级原因。单元格公式调用数据专用库的缓存值接口；不自己计算 Excel 公式。

切块输入是解析器返回的单元文本。空单元发布“已处理但无词”而不调用嵌入，与现有空 PDF 页相同。嵌入失败只重试该单元。重复上传在登记层结束，不进入第二次解析。

父块混合查询的自动发现继续只看 PDF 封口材料。新格式走单元索引，直到将来有单独的非页父块规格。

## 6. 迁移与兼容风险

- 把幻灯片或表格行写进 `page_number` 会让旧阅读页和检索标题显示成 PDF 页。方案拒绝这种写法。
- 新迁移必须是 `018` 及以后，且可重复执行。健康检查里的版本号要与最大迁移一致。不得把库从 17 降回任务旧文里的 15。
- 回填向量行上的 `project_id` 会锁大表，可能和正在进行的入库抢锁。默认不做。
- 按文件名或只按 sha 删除会误伤另一个项目。本方案不提供删除。
- 全局环境变量 `DDA_SEARCH_PARENT_DOCUMENT_IDS` 若只填了项目 A 的材料，项目 B 会跳过自己的父块自动发现并退回页级。这不泄漏正文，但会改变 B 的检索路径。实施页面时不要把当前项目写进这个全局名单；名单仍是进程配置。父块自动发现继续按请求中的项目查询。
- 改变“无地址则选最新项目”会让习惯直接打开检索页的人必须先选项目。这是规格要求，实施时在空状态写明下一步，而不是静默搜最新项目。
- Office 库对损坏压缩包、共享字符串和非常大的表会占用内存。首批限制单文件仍走现有上传上限，并限制单次解析的单元数；超出则该材料部分完成并说明未读范围。
- 关键词 GIN 和向量列是全表索引。新查询必须先连接本项目的材料，再按词项或距离取有界候选。只按词项扫描再在应用层丢弃，不算完成。

## 7. 与遗留任务的实施关系

页面当前项目和隔离回归不依赖新格式，也不依赖 RG-04。  
RG-02 可以先只覆盖 PDF 页。新格式的单元缺口在该格式实施时并入同一清单，避免两套覆盖口径。  
RG-03 的证据标识先覆盖现有 PDF 切片和父块，MCP 与 HTTP 同一服务。新格式的标识使用定位种类，不伪造页范围。  
RG-06 的过滤加在已有项目条件外面。页过滤只对 PDF；其他格式按定位过滤。  
RG-05 的剩余核对不改已放弃的 j4 和跨运行向量缓存。性能改动仍不得跳过来源版本检查。  
RG-07 与报告生成不排进实现队列。对接清单只在对方 Bot 冻结工具调用方式后执行。
