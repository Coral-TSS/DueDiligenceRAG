# 尽调报告 Agent：产品需求规格

版本：0.8
日期：2026-10-23  
状态：用户已确认 P1 范围和分阶段开始开发；各阶段仍需独立验收。  
关联文档：[开发计划](./plan.md) · [环境与材料准备清单](./preparation-checklist.md)

## 1. 产品目标

面向需要编写尽调报告的律师及尽调人员，从用户提供的原始材料出发，自动阅读材料、整理事实、关联依据、核对矛盾、发现待核实事项、进行有依据的法律分析，并按用户模板生成可编辑报告。

用户无需事先建立事实表、证据表或结构化数据库。系统在处理文件的过程中自动形成工作记录。数据识别、重要性筛选、补识别与结果选择均自动完成，不要求用户选框、校正、采用或逐项确认。产品承担律师工作中的资料阅读、整理、核查和起草环节；报告层面的审阅与修订独立于数据识别，不得成为识别流水线的必经步骤。

2026-10-22 已确认：报告阶段由大模型主导事实整理、章节规划、起草、引用核对和修改，复用现有 Agent 框架的通用运行能力；本项目提供材料检索、证据读取和可复用的 Word 等能力及尽调方法包。首轮不以完整事实数据库、知识图谱或自研报告状态机为前置条件。项目内框架运行基线已完成，业务工具与桌面版接入仍未完成。

2026-10-23 当前优先范围：先让本地 RAG 在异常恢复、覆盖说明、有界原文补读、真实质量和性能方面可验证，再接入用户已有 Agent 桌面工具。Word／工作文件工具、尽调 skill 和报告生成暂缓，不删除长期产品要求；Word 优先复用已有能力，必要时补实际缺口。阶段要求与验收见 [P1 规格 RS-01–07](../01-evidence-to-report/spec.md)。

2026-11-07：项目中心增量见 [project-center-spec.md](../01-evidence-to-report/project-center-spec.md)，任务状态只以 [tasks.md](../01-evidence-to-report/tasks.md) 为准。DeepSeek Harness 编排和报告生成改由另一教学 Bot 负责。本仓库提供 MCP 与对接验收，不恢复已删除的 harness-runtime。

本规格说明“做什么、何时算完成”。数据库、模型和程序库等实现选择见开发计划及准备清单。

## 2. 已确认要求与工作假设

### 已确认要求

- **C-01：** 输入包含图片、PDF、Word、Excel、PPT 等原始文档，不要求已有结构化数据。
- **C-02：** 单项目材料可能达到数 GB 或更大，报告可能达到上百页。
- **C-03：** 支持并购、不良资产、IPO 等多种尽调；核心能力复用，专项审查方法可扩展。
- **C-04：** 不同客户或项目的报告模板会调整，系统必须支持模板适配。
- **C-05（2026-10-20 更新）：** 材料、检索资料、项目工作记录和报告保存在本地；用户明确报告生成会调用外网模型，具体服务商、凭据、材料发送范围和预算在接口接入时配置。OCR、视觉复核、向量化和重排序优先本地运行。
- **C-06：** 文档切片、向量化、重排序在本地运行，不以安装 Docker 或自行训练模型为前提。
- **C-07：** 开发采用 SDD，每个功能包先定义需求与验收，再实现和验证。
- **C-08（2026-10-20）：** 采用分层识别：可读文字 PDF／Word 优先原生解析，扫描区域先基础 OCR，重要页及疑难区域按需调用本地小型视觉模型；混合文档按区域分流，并保留重要性漏判的兜底和回补机制。
- **C-09（2026-10-20）：** OCR 评估受控并行处理，任务并发、模型内部线程、内存与其他本地模型预算分别管理；依实测选择配置，不将线程数增加等同于必然提速。
- **C-10（2026-10-20，用户明确纠正）：** 数据识别全程不依赖用户介入。先原生提取或基础 OCR，按报告章节／核心信息需求自动匹配，再对相关扫描页／区域调用本地小型视觉模型。自动重试、选择结果、标记未知／冲突并继续其余处理；不得将用户复核或标注作为运行条件。需求画像及漏判兜底见 [报告信息需求](../01-evidence-to-report/report-information-profile.md)。
- **C-11（2026-10-22）：** 事实整理、章节起草、引用内容核对及修改由大模型通过工具完成；程序负责实际检索、来源定位、文档操作、文件保存和边界检查。方法包指导行为，项目笔记、章节、引用清单与进度分别持久化。通用 Agent 运行机制优先复用成熟框架，不另建一套报告编排引擎。
- **C-12（2026-10-23）：** 当前先完善本地 RAG；已保存处理成果、任务检查位置与当前可检索覆盖分开显示，重启不丢失成果或误报正在运行。支持按范围／真实引用有界补读、保留未知及过期状态，并在固定样本上验证检索质量和资源使用。上述能力在限定样本验收后，接入用户已有桌面 Agent；Word／工作文件和尽调方法包当前不开发。

### 首版范围与工作假设

- **A-01：** 首版面向 Windows 本机、单人使用，中文材料优先；团队共享与多人权限后续另行定义。
- **A-02（已确认，2026-10-19 更新）：** 根据已收到的工商扫描档案和报告样例，用户确认首轮改为公司基本情况与历史沿革，支持扫描／混合 PDF；按 P1-A 基础工程、P1-B 本地阅读检索、P1-C 有来源的章节报告推进。报告作为参考，原件作为证据，分别使用。
- **A-03：** 初次用户测试先使用获准样本；没有材料外发许可时，外部模型保持禁用。
- **A-04（2026-10-22）：** 首轮复用已有 Agent 交互入口及 Word 工具进行报告修订，先交付两章可编辑 Word 草稿；专用报告编辑界面与 Word 外部修改自动回传后置。报告审阅不成为数据识别的必经环节。

法域、报告基准日、交易目的和审查范围由项目设置决定，不能仅凭“并购”或“IPO”名称推断。未知项目设置可以保留为待补充，不阻止材料导入；依赖这些设置的法律分析必须说明缺失条件。

2026-10-19 用户决定：P0 暂不考虑法律部分，法域、法源及法律分析不作为 P1-A/B 的启动条件；后续通过大模型处理法律分析时再细化相应规格。不得把本阶段的文件登记或检索标记为已完成法律审查。

## 4. 交付范围

| 层级 | 包含能力 | 完成含义 |
| --- | --- | --- |
| 首条链路（P1） | 工商扫描／混合 PDF、公司基本情况与历史沿革、参考报告；P1-A 登记与持久化 → P1-B 分页阅读及本地检索 → P1-C 抽取及报告 | 每个子阶段独立验收；A/B 不以生成模型或法律资料已就绪为前提 |
| 首版可用范围（P2–P5） | 多格式批量处理、事实核对、混合检索、受限专项法律分析、模板适配、长报告和增量更新 | 在明确法域、范围及标注样本内通过验收 |
| 扩展范围（P6） | 并购、不良资产、IPO 等专项逐一补齐；内网模型及团队部署扩展 | 每个专项和部署模式单独验证，不以共享界面代替业务覆盖 |

首版应接收 PDF、DOCX、XLSX、PPTX、PNG、JPEG；旧版 DOC/XLS/PPT、加密文件及其他格式必须明确说明支持状态和转换方式，不能静默跳过。旧格式原生处理、压缩包递归展开和特殊行业格式后续按样本决定，不作为首版默认已支持能力。

首版不训练专用模型、不自动对外发送报告、不默认购买或访问商业法律数据库、不提供复杂审批流，也不承诺未经复核的分析可直接作为正式法律意见。

## 5. 正常使用流程

以下是用户可观察的成果顺序，报告阶段的检索、补读、写作和核对由模型按方法包动态决定；不要求自研固定业务状态机。首轮从已处理的小批材料起草两章，覆盖范围与未知事项随稿呈现。

1. 用户创建工作区或直接导入材料；系统自动建立工作记录。
2. 用户选择尽调类型、填写必要范围，并选择或导入报告模板；缺失设置显示待补充状态。
3. 系统显示材料清单、处理进度、失败原因和覆盖范围，逐步生成事实及问题。
4. 系统自动选择识别结果并记录未知、冲突与覆盖限制，继续检索及草稿生成；用户可查看事实与原文，但无需介入数据识别。
5. 系统按审查事项检索和核对证据，形成材料缺失清单及法律分析草稿。
6. 系统按模板生成章节，检查跨章节一致性，列出尚未解决的问题。
7. 用户修改章节并导出 Word；未解决问题和材料范围随版本保留，不伪装成“全部核实”。
8. 新材料到来后，系统展示变化及受影响内容，由用户选择采纳新的章节版本。

## 6. 功能需求

| 编号 | 要求 | 归属阶段 |
| --- | --- | --- |
| FR-01 项目范围 | 保存尽调类型、法域、对象、期间、报告基准日、审查范围与材料发送策略；允许创建信息不完整的草稿工作区。 | P1、P4 |
| FR-02 材料清单 | 每个输入文件具有独立标识、来源、处理结果和版本关系；同名不同内容不能覆盖，重复内容可复用处理结果但保留来源。 | P1、P2 |
| FR-03 文档理解 | 读取段落、标题、条款、表格、备注和图像文字；保留阅读顺序、单位与字段值对应关系。保留源图细节，支持疑难区域辅助识别；识别失败及未支持内容须显式列出。 | P1、P2 |
| FR-04 证据定位 | 关键事实能回到指定文件版本的原文位置。引用位置适应不同格式；无法稳定定位时标记，不编造页码。 | P1、P2 |
| FR-05 事实整理 | 大模型按审查需要整理主体、金额、日期、比例、事件等，通过工具读取证据并保存带出处的工作笔记／章节材料。原文、计算、推断及未知分别标识；首轮不要求先建完整事实数据库。 | P1、P3 |
| FR-06 实体与关系 | 区分公司别名、关联主体、债权债务及担保关系；合并存在歧义时保留待确认，不仅按名称相近合并。 | P3、P6 |
| FR-07 检索与查证 | 同时支持具体名称编号和语义问题，返回原文依据。检索仅限当前获准材料；完整清单和汇总需遍历相应范围，不只选若干相似片段。 | P1-B 基础检索；P3 强化 |
| FR-08 核对与计算 | 比较主体、时间、币种、单位及义务；数值计算给出输入及计算口径，识别不一致。不同期间、草案与生效文件不能不加区分比较。 | P3 |
| FR-09 缺失与覆盖 | 根据审查事项列出已覆盖、待处理、无法处理、未提供及不适用项。“没有找到”不能自动写成“不存在”。 | P2–P4 |
| FR-10 审查方法 | 审查方法包（skill）定义所需材料、检查项、分析方法及写作规则；项目发现单独保存。方法包支持版本与组合，不把全部项目记忆塞入一个摘要。 | P4、P6 |
| FR-11 法律分析 | 每个问题关联事实、支持和反向证据、适用法源及版本、适用理由、未决条件与建议；缺少法源或关键事实时说明限制，不补造引用。 | P4 |
| FR-12 模板适配 | 大模型读取模板后映射业务事项，通过文档工具调整章节、正文和表格；无法映射或新增事项明确提示，保存模板版本。不要求预先硬编码所有模板。 | P1、P5 |
| FR-13 报告与修订 | 大模型分章起草和核对名称、日期、金额及引用内容，工具执行编辑、保存与 Word 导出并检查引用是否存在／可定位。保存章节、引用及修订版本，不能用链接有效代替内容得到证据支持。 | P1、P5 |
| FR-14 增量更新 | 新增、替换、撤回材料或纠正事实后，标记依赖内容过期，展示变化；只重算受影响部分，不静默覆盖人工修订。 | P5 |
| FR-15 任务恢复 | 显示处理阶段、数量、失败项和可执行恢复动作；支持停止新增处理、恢复和局部重试，避免重复记录及反复处理已完成内容。 | P1-A 登记持久化；P2 批量任务恢复 |
| FR-16 本地与模型边界 | 本地保存和检索可独立运行；外部模型发送须满足项目策略，首次批量抽取同样受约束。关闭外发后，不能调用远程向量或重排序服务代替本地模型。 | P1、P6 |
| FR-17 操作留痕 | 记录材料、事实、规则、法源、模型和报告版本的关联及用户修改。默认运行日志不复制完整材料、密钥及敏感正文。 | P1–P5 |
| FR-18 图像质量 | 分开记录处理成功、机器选择结果及质量／未知状态；按报告需求自动筛选扫描重要页并调用视觉模型，分歧自动重试或保留未知，不等待用户确认。开发侧用独立原件参考样本评测，不把标注工作交给产品用户；模型高分、一致输出或旧报告答案不能证明正确。具体要求见 P1 规格 B-Q／B-R。 | P1-B 优先，P2 强化 |

法源与公司材料分别管理：文件中提到的法律条文须经过法源核验；文档中的指令只是材料内容，不能改变系统的权限和处理规则。

## 7. 状态与边界行为

| 状态／场景 | 用户可见行为 |
| --- | --- |
| 空工作区 | 显示导入材料和选择模板入口；不生成虚构正文。 |
| 正在处理 | 显示已发现、已完成、失败、待核实数量与当前阶段；界面可继续使用。 |
| 部分完成 | 可查看已完成结果，标明未覆盖范围；导出只能以草稿及相应限制说明呈现。 |
| 处理成功 | 显示本次覆盖情况、待核实事项、章节版本和导出入口；处理成功不等于所有法律问题已解决。 |
| 失败 | 区分文件损坏、密码保护、格式不支持、模型失败和存储不足，并提供针对性的恢复操作。 |
| 断网／模型不可用 | 已下载模型的本地解析与检索继续可用；依赖外部模型的任务暂停或失败，保留进度。 |
| 资料版本冲突 | 展示版本及其关系；不以最后上传时间代替法律生效判断。 |
| 日期、币种或单位缺失 | 保持未知并说明影响，禁止默认补齐成确定事实。 |
| 表格公式无可靠结果 | 展示公式或原始值及缺失情况，不把空缓存当作零；重新计算时注明来源和方法。 |
| 跨页条款或表格 | 合并必要上下文，保留各部分来源；上下文不足时不直接下完整结论。 |
| 印章、签字、手写或低清晰度区域 | 保留原图并标记识别不确定性；外观识别不等于真实性或法律效力认证。 |
| 修订、批注、隐藏工作表或嵌入对象 | 已提取时标识其性质；尚不支持读取时列入覆盖限制，不假定已审阅。 |
| 模型超时与取消 | 保存任务状态；提示已经发送的请求可能仍产生费用，不假装取消一定撤回外部调用。 |
| 撤回材料 | 从当前检索范围排除并标记依赖结论过期；历史记录按保留策略处理。永久清除另行确认范围。 |

## 8. 非功能要求

- **NFR-01 数据控制：** 本地文件不因导入自动上传；外发策略覆盖文字、图片、表格、摘要、向量及运行日志。跨项目数据不能混入结果。
- **NFR-02 可恢复性：** 关闭应用或后台任务中断后，可以恢复已保存进度；重复运行不重复增加同一事实或材料记录。
- **NFR-03 可追溯性：** 报告版本能够追踪使用的材料、规则、法源和人工修改；摘要可以重建，不能成为唯一证据。
- **NFR-04 容量：** 支持分批处理数 GB 材料，不要求一次加载全部材料。以固定批次逐步扩大测试，并报告页数、扫描比例和设备条件。
- **NFR-05 性能：** 第一轮规格以实测吞吐、峰值内存、单页费用和检索耗时建立基线；容量验收前必须记录明确目标值，不得以“较快”通过验收。等待操作应有进度和取消入口。
- **NFR-06 可用性：** 核心流程支持键盘、清晰焦点、文字错误提示；状态不只靠颜色表达。首版以桌面使用为验收范围。
- **NFR-07 可维护性：** 模板、审查方法、法源及模型升级后，旧报告仍能识别其来源版本；更换向量模型后需重建相应索引，不能混用不兼容向量。
- **NFR-08 备份：** 原件、工作记录、模板与报告可以完整备份并恢复；索引是否可重建须明确，备份不能只有向量数据。

### 质量门槛草案

下列数值是供业务评审的首版目标，不是已达到的效果或所有案件的保证；通过专业标注样本确认后，在首次盲测前冻结。未确认时不能宣称生产可用。

| 指标 | 建议首版目标 | 测量定义 |
| --- | --- | --- |
| 材料登记覆盖 | 100% | 每个输入均有状态，允许明确失败，不允许静默遗漏。 |
| 关键事实准确率／召回率 | ≥95%／≥90% | 与人工标注比较，主体、字段、值、单位和时点一致才计正确；推断不计作抽取命中。 |
| 引用可定位率 | 100% | 输出引用均指向已保存的有效来源记录；材料撤回时必须显式标记。 |
| 事实陈述证据支持率 | ≥98% | 人工抽检确认原文真正支持陈述及其限定条件，引用存在不等于支持。 |
| 检索 Recall@20 | ≥95% | 对有标准相关证据的查询，前 20 项覆盖的标准证据占比；无答案查询单独评测。 |
| 法律问题召回 | ≥90%，且约定的关键必检问题不得遗漏 | 由业务人员事先标注问题与严重程度，并同时审查无依据风险提示，不能靠堆砌风险提高召回。 |

评测应包含正例、无答案、冲突、旧版本、跨页表格和低质量扫描等情况。调试集与盲测集按项目或文件组隔离，同一文件的不同切片不能分散到两组。建议首轮准备约 30–50 份文件、50 个查询、200 条关键事实及 20 个问题样例；这只是起步规模，不能证明覆盖全部尽调类型。

## 10. 专项扩展规则

| 专项 | 在通用能力之外必须单独定义和验证 |
| --- | --- |
| 并购 | 交易目的、主体范围、历史沿革、重大合同对交易的影响及跨章节关联。 |
| 不良资产 | 资产包逐笔台账，债权、债务人、担保、诉讼或执行材料之间的关系；逐笔缺失和金额口径。 |
| IPO | 主体与历史期间范围、披露一致性、各期变化、专项材料完整性及适用审查规则。 |
| 其他 | 新增审查方法包、材料要求、事实类型和验收样本，不仅增加一个类型名称。 |

以上仅定义扩展方向，不构成完整法律审查清单。每个专项须由业务人员确认审查范围和法源。
