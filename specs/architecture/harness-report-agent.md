## 职责与接入

| 部分 | 职责 |
| --- | --- |
| 生成模型 | 自主检索／补读、整理事实、建立时间线、规划和起草章节、回读原文核对引用、修改正文 |
| Harness | 尽量复用现有 Agent 循环、会话持久化、上下文管理、工具机制及交互入口 |
| Python 本地服务 | 保留 PDF／OCR／视觉／向量化工作进程、PostgreSQL／pgvector 和重排序；提供项目绑定的工具适配 |
| RAG／证据工具 | 检索、分页清单、读取原文和来源元数据，提供覆盖／版本／未知状态，不自行编写报告结论 |
| Word／工作文件工具 | 按模型调用读取模板、编辑章节／表格／引用、保存工作记录与输出 Word，返回真实操作结果 |
| 尽调 skill | 两章材料要求、检索策略、完整清单检查、未知／冲突处理、写法、引用核对和保存时机；不含客户事实 |

优先通过 Python MCP 服务包装现有业务能力，避免将 RAG 改写为 TypeScript 原生插件。首轮用本地 stdio；本地服务模式确有需要时再采用 Streamable HTTP。现有 FastAPI 的搜索端点不是 MCP 端点，仍需实现薄适配。

先使用 Harness 既有交互入口完成工具闭环；嵌入现有 FastAPI 页面时再评测官方 Python SDK 驱动独立运行时的方案。profile 采用明确的工具清单，只暴露完成尽调所需能力；具体 profile 和 Word 工具复用来源在 C-T01／03 记录，不假定默认预设已装好所需工具。

## 拟暴露的最小工具契约

以下均为拟新增或适配的工具名，不是已经可以调用的接口。每次会话由服务端绑定 project／report run，不能仅靠模型自觉传对项目标识。

| 能力 | 输入／输出及实现边界 |
| --- | --- |
| `get_material_coverage`、`list_materials` | 返回材料类型、总页数、处理和有效索引覆盖、未知／失败、来源版本；清单分页，不把历史任务批次数字当实时有效索引数 |
| `search_evidence` | 复用现有搜索＋重排序；返回原文片段、真实 evidence／document 标识、页码、版本、质量状态与覆盖。当前接口只取重排前 5 项，不能代表完整审查 |
| `read_evidence` | 按来源标识读取上下文，或按材料＋页范围分页补读；保留稳定定位、返回长度与续读游标。不让模型一次取回整个卷宗 |
| 工作文件读写 | 在当前报告目录读写提纲、笔记、时间线、引用清单和章节；限定相对路径、原子保存／修订版本，支持幂等操作或版本冲突反馈 |
| Word 工具组 | 读取模板结构及稳定段落／表格位置，按模型内容编辑章节和引用，校验可定位引用并保存／导出。优先验证现成工具，缺口薄封装；docxtpl 只在占位符适用时采用 |

“历次变更／全部股东”等任务由模型按 skill 驱动材料清单和页范围遍历，工具只提供有界分页，不建设一个硬编码尽调规则引擎。未读页面单列，模型不能把 top-k 命中或笔记摘要宣称为全卷覆盖。

引用内容核对由模型读取原文执行；工具检查真实标识、项目归属、版本和定位，返回失效／未知状态。这种机械检查不证明语义支持，不单独建设一个自动判断所有事实真假的业务服务。导出前不存在或无法解析的引用须修复／明确标记，不能伪造页码；确认的内容缺失与冲突随草稿保留。

## 持久化与恢复

报告工作目录建议位于业务 data_dir 下的 `reports/{project_id}/{report_run_id}/`，与不可改写的原件和 testing/ 分开。保存提纲、事实／时间线笔记、覆盖说明、引用清单、章节草稿和 Word 版本；先采用 Markdown／轻量 JSON，无完整事实表或知识图谱前置要求。

保存最小运行清单：project／run／session、skill／模型／模板版本、工作文件、输出和最后已保存阶段；Harness home 显式选择并与项目会话映射。会话压缩不能丢失唯一的章节和引用，续写先读取工作文件。

Harness 会话恢复不恢复 OCR／向量工作进程，现有后台任务和残留 pause_requested 问题继续由材料链路处理（PR-05）。Word 重试不得重复追加相同章节；来源变化后重新读取相关证据并产生修订，不悄然覆盖既有报告。

## 模型和本地边界

Harness、本地 MCP、原件、RAG、Word 和工作文件在本机；生成模型可通过获准 API 运行。模型可见的工具结果、笔记、模板片段、草稿和会话内容都属于可能外发的数据，按配置范围执行，不仅控制最初检索请求。服务端项目边界和 Word 操作校验不依赖提示词。

API 服务商、凭据、发送范围和预算仍是实际外网报告调用的前置条件；工具与合成验证可先实施。官方工具超时／取消信号须传递至本地操作；报告会话停止和材料任务暂停分别显示，未保存推理不承诺恢复。

## 拟新增文件与实施顺序

| 位置（拟定） | 工作 |
| --- | --- |
| `src/dd_agent/mcp_server.py`、`tools/evidence.py` | 复用服务层并暴露项目限定的检索／证据／覆盖工具，CLI 入口与现有 serve 分开 |
| `tools/word.py`、`tools/workspace.py` | 现有可复用文档能力的薄适配、项目工作目录和引用清单读写 |
| `agent_runtime.py`（需要嵌入现有应用时） | 薄的 Harness 启动、会话关联、事件转发和停止接口，避免自研模型循环 |
| `agent_profiles/`、尽调方法包目录 | 固定版本对应的 profile／patch、工具清单和两章 skill；具体格式依选定版本验证，不在本次写未经测试的 YAML |
| `testing/tests/`、`testing/records/`、`testing/runs/` | 工具隔离、引用、文档幂等、失败／恢复、真实模型两章闭环与 Word 渲染记录 |

执行顺序：版本／profile 小验证 → RAG 和补读 → Word／工作文件 → 尽调 skill → 模型自主两章草稿／引用核对／导出 → 中断恢复与真实小批验收。只接入一个 Agent，不以多 Agent、事实关系服务、专用编辑 UI、全量 649 页或全部多格式完成作为起步条件。

通过条件以 P1-C C-01–08 为准：必须记录真实工具调用和实际 Word 文件，不能只证明模型能聊天。检查事实完整性／支持关系、未知与覆盖说明及排版；合成通过与真实生成通过分开记录。材料侧 B-Q／B-P 和 PR-05 继续推进，法律分析后置。
